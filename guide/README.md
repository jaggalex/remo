# Как устроен портал документации

`guide/` — исходники Product Guide. Сборка и правила те же, что у встроенной помощи
(`content/help`), потому что логика лежит в одном месте: `scripts/docs-core.mjs`.

## Раскладка

```
guide/
├── sections.json        разделы навигации и их порядок
├── coverage.json        матрица «возможность → документы»
├── trace.json           служебная трассировка: страница → ADR, код, тесты
├── help-links.json      тема встроенной помощи → страница портала
├── style.md             стандарт текста и чек-лист приёмки
├── theme/               CSS портала и клиентский поиск
├── <раздел>/<страница>/
    ├── meta.json        id, type, status, order, title/summary RU+EN, хеш перевода
    ├── ru.md            источник
    └── en.md            перевод
```

Сборка также пишет в `docs-site/`:

| Файл | Что это |
|---|---|
| `llms.txt` | карта документации для LLM: разделы, страницы, EN-резюме и абсолютные ссылки |
| `llms-full.txt` | все EN-страницы одним текстом для агента, который не переходит по ссылкам |

Обе ссылки публичные (`https://docs.remo.letii.ru/guide/llms.txt` и `.../llms-full.txt`),
не дают доступа к продукту и собираются из тех же исходников, что и портал. Вход для
человека — страница `overview/ai`, ссылка в шапке и пункт «Для AI-агента» в оглавлении.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm guide:build` | собирает `docs-site/` |
| `pnpm guide:check` | проверяет источники и свежесть сборки, ничего не пишет |
| `pnpm guide:accept` | записывает текущий хеш RU в `meta.json` после перевода |
| `pnpm guide:serve` | локальный просмотр собранного портала на `http://localhost:8088/guide/` |
| `pnpm guide:audit` | браузерная приёмка портала (входит в `pnpm verify --e2e`) |

`guide:check` входит в `pnpm verify` и падает, если:

- ссылка ведёт на несуществующую страницу, тему помощи или раздел;
- страница ссылается на `spec/` или `ADR.md`;
- в теле нет H2, есть H1 или пропущен уровень заголовка;
- EN-перевод устарел (хеш не совпадает);
- `json`-пример не парсится;
- страница недостижима по ссылкам от `overview/index`;
- в `coverage.json` меньше двух видов документов на возможность;
- `trace.json` ссылается на несуществующий файл или ADR;
- у темы помощи нет страницы портала.

## Порядок работы над страницей

1. Соберите факты по коду и `trace.json`, а не по памяти.
2. Напишите `ru.md` по шаблону из `style.md`.
3. Переведите `en.md` отдельным проходом (структура и ссылки — один в один).
4. `pnpm guide:accept` → `pnpm guide:build`.
5. Дайте страницу свежему читателю по чек-листу `style.md` и закройте замечания.

## Интерфейс

Портал — три колонки от 1280 px (меню 260, статья 640, оглавление 200), две от 768 px
(оглавление над статьёй) и одна до 767 px (меню — выезжающая панель). Типографика чтения —
16 px / 1.65, колонка 640 px, то есть 65–80 символов в строке. Все геометрические значения
и размеры шрифтов — переменные `--guide-*` в начале `guide.css`.

**Поиск.** Диалог открывается кнопкой, `Ctrl+K` / `⌘K`, закрывается `Esc`; стрелки выбирают
результат, Enter открывает, фокус возвращается на кнопку. Индекс — `docs-site/search.json`,
данные берутся через `createSearchSource(url)` в `theme/search.js`: чтобы подключить
настоящий поисковый сервис, заменяется только эта функция, остальной файл не меняется.

**Темы.** Светлая, тёмная и системная; выбор хранится в `localStorage` под ключом
`guide.theme`. Тема выставляется inline-скриптом в `<head>` до первой отрисовки, поэтому
страница не мигает. «Системная» следит за `prefers-color-scheme` без перезагрузки.

**Меню.** Группы разделов — `<details>`; состояние свёрнутости хранится в
`localStorage` (`guide.nav.<раздел>`), текущий раздел раскрыт всегда.

## Компоненты контента

В Markdown доступны контейнеры; HTML не принимается.

```md
:::note
Обычное примечание.
:::

:::tip
Совет.
:::

:::warning
Требует внимания.
:::

:::danger
Необратимое действие.
:::

:::actions
[Начать работу](/guide/start/quickstart) — рабочая комната за десять минут.
:::

:::tabs
:::tab Запрос
```bash
curl …
```
:::
:::tab Ответ
```json
{ "ok": true }
```
:::
:::
```

Метка примечания и заголовки вкладок берутся из языка страницы, поэтому в `ru.md` и
`en.md` текст контейнера переводится, а имена контейнеров — нет.

Изображения лежат в `guide/assets/` и копируются в `docs-site/assets/`; ссылка в тексте —
`![alt](/guide/assets/file.svg "подпись под рисунком")`. Картинка рендерится как `<figure>`
с подписью и открывается в новой вкладке для увеличения; сборка падает, если файла нет.

Скрипты интерфейса: `copy.js` (копирование кода и ссылок с подтверждением), `tabs.js`
(ARIA-вкладки), `map.js` (карточки и фильтры карты возможностей), `theme.js`, `nav.js`,
`toc.js`, `search.js`. Без JavaScript страница остаётся читаемой: вкладки показываются
секциями, поиск не открывается, но ссылки работают.

## Приёмка

`pnpm guide:audit` поднимает собранный портал и проверяет в Chromium: отсутствие
горизонтального скролла на 360/390/768/1024/1440, посадку якоря ниже шапки, skip-link
первым в Tab, фокус в drawer и в диалоге поиска, сохранение темы после перезагрузки,
точное содержимое буфера при копировании, фильтр и карточки карты возможностей, а также
разметку всех страниц (один H1, `main`, skip-link, отсутствие мёртвых `#`-ссылок).
Скрипт входит в `pnpm verify --e2e`.

## Публикация

`docs-site/` — артефакт, в git не попадает. nginx раздаёт его по `/guide/`
(`deploy/nginx-remo.conf`); портал не требует отдельного контейнера или процесса.
Значимый релиз обновляет затронутые страницы и историю изменений, но сборка и гейт
идут на каждый коммит.
