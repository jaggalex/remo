## Что резервировать

| Что | Почему |
|---|---|
| База комнат (`pg_dump`) | комнаты, доступ, журнал, события, токены |
| `REMO_KEK` | без него ключи провайдеров и секреты вебхуков не расшифровать |
| `.env` | настройки, без которых установка не поднимется |
| Каталог якорей (`REMO_AI_ANCHOR_DIR`) | головы хеш-цепочки журнала |

База метрик — отдельная; её потеря не влияет на комнаты, но историю продуктовых событий восстанавливать будет не из чего.

## Шаги: бэкап

```sh
cd /srv/remo
sudo -u remo pnpm db:backup
sudo -u remo pnpm db:backup:list
```

Скрипт использует `pg_dump` или контейнер compose, хранит последние 14 дампов (`REMO_BACKUP_KEEP`) и складывает их в `backups/`.

## Шаги: восстановление

```sh
systemctl stop remo-sync
sudo -u remo pnpm db:restore backups/<файл> --yes
systemctl start remo-sync
```

Восстановление деструктивно: без `--yes` оно ничего не делает, перед заменой сохраняет страховочную копию и отказывается перезаписывать базу с комнатами без `--force`.

## Проверка

- `pnpm db:backup:list` показывает сегодняшний файл.
- Раз в месяц восстановите копию на тестовой установке и откройте комнату: **бэкап, который никогда не восстанавливали, — это надежда, а не резерв**.
- Проверьте, что KEK из резерва расшифровывает секрет: добавьте ключ провайдера на тестовой копии.

## Отдельно: бэкап комнаты

Экспорт комнаты (**Экспорт → Бэкап комнаты**) — это не резерв установки: он содержит одну комнату и не содержит доступ, журнал и ключи. Он нужен человеку, `pg_dump` — администратору.

Бэкап комнаты версии 2 включает объекты, текст, канбан, имена групп, теги, порядок
презентации и комментарии; замок объекта восстанавливается вместе с объектом. Импорт
заменяет комнату целиком, включая обсуждение: пустой список комментариев очищает треды.
Имена авторов сохраняются, связь с аккаунтом — нет.
