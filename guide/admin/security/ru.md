## Границы

| Что | Как защищено |
|---|---|
| Сессия | httpOnly cookie, `SameSite=Lax`, `Secure` в production |
| Пароль | хеш на сервере, проверка постоянного времени |
| Секреты провайдеров и вебхука | конверт: свой DEK, обёрнутый KEK; KEK не в базе |
| Токены интеграций | только SHA-256 в базе, секрет показывается один раз |
| Токены агентов | хеш, срок, отзыв |
| Публичная ссылка | без токена, только чтение, пароль и срок по желанию |
| Метрики | токен в production; прокси закрывает `/api/metrics` снаружи |
| Read-only сокет | тип и шаг читаются varint-декодером; разрешены awareness и один `syncStep1`, update и `syncStep2` отбрасываются |
| Приглашение | токен — bearer-секрет; email получателя проверяется до выдачи прав, внутри транзакции |
| Метаданные комнаты | без доступа `/access` отвечает 404 и не отдаёт название, организацию и visibility |
| Исходящие AI-запросы и вебхуки | только HTTPS, проверка всех DNS-адресов на каждой доставке, привязка к IP, запрет редиректов; `ALLOW_PRIVATE` — явное исключение |
| Комментарии | только аккаунт с доступом; ссылка-посетитель обсуждение не видит |
| Комната без владельца | закрыта для работы: действия получают `403`, пока у комнаты нет владельца; экран доступа сообщает, что владельца нет; ссылка не даёт редактирования |
| Квоты записи | скорость и размер комнаты ограничены; при превышении соединение закрывается с `4429` или `4413`, правки остаются в текущей вкладке |
| Аудит правок | одна запись на сессию, комнату и окно 60 с: число правок и байт, id объектов и поля; содержимое не пишется |
| Замок | координация правок, не ACL; сырой клиент с `board.edit` может обойти |

## Изоляция организаций

Все таблицы с данными организаций — контент комнат, доступ, организации и команды, приглашения, токены интеграций, агенты, аудит, журнал AI и очередь событий — защищены построчной изоляцией (RLS): строка видна только в контексте своей организации. Сервис работает как `remo_app`: только DML, без владения таблицами и без `BYPASSRLS`; схема и обслуживание идут от owner-роли, которая должна быть superuser или иметь `BYPASSRLS`.

Аккаунты, сессии, токены агентов, ключи провайдеров и служебные метаданные схемы остаются вне изоляции организаций: это граница входа, они читаются до того, как организация известна. Для них действуют свои хеши, сроки и шифрование.

## Что нельзя оставлять по умолчанию

1. **`REMO_KEK`** — 32 байта base64, хранится вне сервера и резервируется. Потеря KEK делает сохранённые ключи провайдеров нечитаемыми.
2. **`NODE_ENV=production`** — иначе cookie не `Secure`; без HTTPS вход будет выглядеть сломанным.
3. **`REMO_METRICS_TOKEN`** — иначе `/metrics` отвечает 404 (что лучше, чем открытые метрики).
4. **`REMO_CORS_ORIGIN`** — конкретный origin, не `*`, если используете cookie.
5. **Postgres на loopback** — `POSTGRES_PORT=127.0.0.1:5432` и `ufw`.
6. **`REMO_WEBHOOK_ALLOW_PRIVATE`** — только если действительно нужен внутренний эндпоинт.
7. **Роли базы** — сервис работает как `remo_app` (только DML, без владения таблицами и без `BYPASSRLS`), owner — только для схемы и обслуживания. Не запускайте сервис от owner-роли.

## Публичная ссылка

Ссылка — свойство комнаты, а не токен: она даёт только чтение и никогда не даёт экспорт или бэкап. В меню аккаунта → **Активные сессии** видно браузеры, где выполнен вход, и можно завершить лишнюю сессию, не меняя пароль. Смена пароля по-прежнему закрывает все открытые браузеры. Отзыв ссылки не отзывает персональные роли.

## Что стоит проверить на установке

- `/api/metrics` снаружи отвечает 404.
- Порт 1234 и 5432 не видны из интернета (`ss -ltnp`).
- `.env` доступен только пользователю сервиса.
- `pnpm db:rls --check` подтверждает, что все таблицы с данными организаций защищены.
- `pnpm db:rls:enable --check` подтверждает применённый набор; owner-роль — superuser или с `BYPASSRLS`.
- Роль `remo_app` не владеет таблицами и не имеет `BYPASSRLS`.
- `pnpm db:orphans --list` не находит комнат без владельца; до обновления их архивируют (`--archive --yes`), а с известным владельцем назначают (`--assign <room> --user <email>`).
- Комната без владельца не даёт работать: действия получают `403`, пока у комнаты не появится владелец; экран доступа при этом показывает причину.
- Резервная копия KEK лежит отдельно от базы.
- Комната без доступа отвечает 404 на `/api/boards/<id>/access`, без названия и организации.
- Подделанный varint-кадр от viewer не меняет документ.
- Приглашение, открытое чужим аккаунтом, не выдаёт членство и остаётся доступным получателю.
- Custom AI endpoint с `[::ffff:127.0.0.1]` отклоняется при сохранении.
