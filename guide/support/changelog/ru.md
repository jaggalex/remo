## Как читать

Версия схемы — номер в таблице `schema_meta`. Сервис применяет `schema.sql` при старте и
не трогает базу, если версия уже актуальна. Продуктовые изменения выходят вместе с версией
схемы; отдельного «релиза документации» нет.

## Версии схемы

| Версия | Что добавила |
|---|---|
| 4 | очередь событий `event_outbox` |
| 5 | вебхук организации `org_webhooks` и поля повторов у событий |
| 6 | токены интеграций `integration_tokens` |
| 7 | ключ дедупликации событий `dedupe_key` |
| 8 | приложения организации `org_apps` |
| 9 | комментарии: `comment_threads`, `comments`, `comment_reads` |
| 10 | план агента: `agent_task_plans`, статусы `proposed`/`approved`/`applied`/`rejected` |
| 11 | исходные данные задачи: `agent_task_inputs` с источником `selection` |
| 12 | настройки интерфейса в аккаунте: `users.theme`, `users.lang` |
| 13 | привязка аудита к сессии: `audit_events.session_id` |
| 14 | индексы идемпотентности команд и задач |
| 15 | обязательный уникальный `@ник`: `users.handle` |
| 16 | личные организации и домашняя страница: `orgs.kind`, `boards.icon`, `boards.created_at`, `boards.created_by` |
| 17 | `org_id` у таблиц, привязанных к комнате: заполнение существующих строк и триггер для новых |
| 18 | построчная изоляция организаций (RLS): политики на все таблицы с данными организаций, роль приложения `remo_app`, функции для поиска организации, задач агента и очереди событий |

Версии 1–3 — ранняя линия: комнаты, доступ и журнал команд. Базы, созданные раньше,
обновляются тем же `schema.sql` при старте.
