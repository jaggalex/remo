# Приложения (first-party)

Первая точка расширения доски (ADR-098). Приложение — это **манифест в реестре сервера**:
организация ставит его по id, сервер записывает свой манифест в `org_apps`, а доска рисует
присланную схему своими компонентами. Чужой код в origin продукта не исполняется — ни
JavaScript, ни HTML, ни iframe.

## Манифест

```js
{
  id: "app.hello",
  version: 1,
  nameKey: "apps.hello.name",
  descriptionKey: "apps.hello.description",
  capabilities: ["board.read"],
  panel: {
    type: "panel",
    titleKey: "apps.hello.name",
    children: [
      { type: "text",   id: "greeting", key: "apps.hello.greeting", params: ["username"] },
      { type: "button", id: "say",      labelKey: "apps.hello.say", action: "app.hello" }
    ]
  },
  actions: {
    "app.hello": { capabilities: ["board.read"], run({ user }) { … } }
  }
}
```

Правила, которые проверяет `apps.test.mjs`, а не браузер:

| Правило | Почему |
|---|---|
| Словарь узлов закрыт: `panel`, `text`, `button`, `field` | неизвестный узел — это дефект манифеста, хост его не рисует и не «выполняет» |
| Все видимые строки — ключи i18n (`key`, `titleKey`, `labelKey`) | язык, формулировки и экранирование остаются у хоста; литерал в манифесте валит тест |
| Кнопка ссылается на объявленное действие | нельзя позвать то, чего нет в манифесте |
| В `capabilities` — только возможности доски | приложение не может попросить больше, чем даёт доступ к доске |

## Установка и выключение

| Метод и путь | Кто | Что делает |
|---|---|---|
| `GET /orgs/:id/apps` | участник организации | список **включённых** приложений с их панелями |
| `POST /orgs/:id/apps` `{appId}` | `org_admin` | поставить или переустановить; манифест берётся из реестра |
| `PATCH /orgs/:id/apps/:appId` `{enabled}` | `org_admin` | выключить/включить |
| `DELETE /orgs/:id/apps/:appId` | `org_admin` | удалить |

Выключенное приложение исчезает из списка, и его действия отвечают `404`: kill switch
убирает всю поверхность, а не только кнопку. Установка, включение, выключение и удаление
пишутся в аудит (`app.installed`, `app.enabled`, `app.disabled`, `app.removed`).

## Действие

`POST /orgs/:id/apps/:appId/invoke` `{ boardId, action }`.

- нужен доступ к доске `board.read` у того, кто зовёт: сессия или токен интеграции
  (тогда ещё и scope `board.read`);
- доска должна принадлежать той же организации, иначе `404`;
- объявленные `capabilities` действия проверяются по фактическому доступу;
- результат — **текст для хоста**, а не HTML: `{ message: { key, params } }`;
- каждое нажатие — `app.invoked` в аудите и событие `app.invoked` в outbox (Q5), поэтому
  интеграция может на него отреагировать.

`app.hello` возвращает `apps.hello.greeting` с именем вызвавшего: «Привет, {username}!».

## Панель на доске

Кнопка **«Приложения»** в верхней панели открывает диалог. Он показывает приложения
организации, которой принадлежит доска; если организации нет — объясняет это. Строки
берутся из `i18n.tsx` (RU + EN), стили — только из токенов дизайн-системы, тема помощи —
`apps.hello`.

## Границы

Нет маркетплейса, сторонних приложений, iframe, загрузки внешнего кода, биллинга и
каталога. Когда что-то из этого появится, это будет отдельным ADR, а не настройкой.
