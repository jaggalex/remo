# Вебхук организации

Один подписанный вебхук на организацию (ADR-094, ADR-095). Он доставляет доменные
события, которые порождают серверные команды: изменения, сделанные через
`POST /boards/:id/commands`, и (после Q5.4) записи агентов.

Это **первая сторона**: получатель — интеграция, которую вы написали сами. Маркетплейса,
нескольких получателей и чужих iframe здесь нет и в плане нет.

## Что и когда приходит

Событие создаётся в момент выполнения команды и попадает в очередь `event_outbox` **в той
же транзакции**, что и запись идемпотентности. Значит: событие есть тогда и только тогда,
когда команда записана; повтор команды с тем же `Idempotency-Key` не создаёт второе
событие.

Пока событие лежит в очереди, его забирает дренаж и отправляет на ваш эндпоинт. Доставка —
**at-least-once**: одно и то же событие может прийти дважды (например, если мы не успели
записать «доставлено»). Дедуплицируйте по `id`.

```json
{
  "id": "9f0c3a4e-6f3a-4e57-9a2f-5d1c0d1c9b11",
  "type": "board.item.created",
  "orgId": "3f2c7d1a-8e4b-4c6a-9f01-2b3c4d5e6f70",
  "boardId": "roadmap-1a2b3c4d",
  "actor": { "id": "5b0e...", "type": "user" },
  "subject": "item_7c1e2f3a9b4d",
  "payload": { "objectType": "sticky_note" },
  "occurredAt": "2026-10-27T12:34:56.789Z"
}
```

**Содержимого доски в событии нет.** Только идентификаторы, типы и счётчики. Если
получателю нужен текст, заголовок или геометрия — он читает объект через API со своими
правами. Это правило, а не временное состояние: событие по умолчанию должно быть
безопасно отдать третьей стороне.

## Заголовки и подпись

| Заголовок | Значение |
|---|---|
| `X-Remo-Event` | `id` события — ключ идемпотентности |
| `X-Remo-Event-Type` | например `board.item.created` |
| `X-Remo-Attempt` | номер попытки, начиная с 1 |
| `X-Remo-Signature` | `t=<unix>,v1=<hex>` |
| `Content-Type` | `application/json` |

Подпись — HMAC-SHA256 секретом вебхука по строке `"<t>.<точное тело запроса>"`:

```js
import { createHmac, timingSafeEqual } from "node:crypto";

function verify(secret, rawBody, header, now = Date.now()) {
  const parts = Object.fromEntries(header.split(",").map((p) => p.split("=")));
  const timestamp = Number(parts.t);
  const given = Buffer.from(parts.v1, "hex");
  const expected = Buffer.from(
    createHmac("sha256", secret).update(`${timestamp}.${rawBody}`).digest("hex"),
    "hex",
  );
  // Окно против повтора: пять минут.
  if (!Number.isFinite(timestamp) || Math.abs(now / 1000 - timestamp) > 300) return false;
  return given.length === expected.length && timingSafeEqual(given, expected);
}
```

Подписывается **тело до разбора JSON** — сравнивайте с сырыми байтами, а не с
`JSON.stringify(parsed)`.

## Ответ и повторы

- `2xx` — доставлено, событие помечается опубликованным.
- любой другой ответ, таймаут (5 с) или ошибка соединения — попытка записывается, и
  событие уходит в повтор по лестнице: 10 с, 30 с, 2 мин, 10 мин, 30 мин, 1 ч, 3 ч.
- после восьмой неудачной попытки событие попадает в **DLQ** (`dead_at`), автоматических
  повторов больше нет.

DLQ — это строка в очереди, а не папка с логами: её видно в `GET …/deliveries?dead=1`, и её
можно переиграть.

## Администрирование

Все маршруты — только для администратора организации и пишут аудит.

| Метод и путь | Что делает |
|---|---|
| `GET /orgs/:id/webhook` | конфигурация: `url`, `enabled`, `fingerprint`, `lastDeliveryAt`, `lastError`. Секрета в ответе нет |
| `PUT /orgs/:id/webhook` `{url}` | создать или заменить эндпоинт; возвращает **секрет один раз** |
| `POST /orgs/:id/webhook/rotate` | новый секрет; старый перестаёт проверяться; возвращает секрет один раз |
| `DELETE /orgs/:id/webhook` | удалить эндпоинт и секрет; события больше не отправляются |
| `GET /orgs/:id/webhook/deliveries?limit=50&dead=1` | последние события организации и их состояние |
| `POST /orgs/:id/webhook/replay` `{eventIds?}` | вернуть в очередь: указанные события или все «мёртвые» |

Секрет имеет вид `whsec_…`, хранится в конверте (свой DEK, обёрнутый KEK, — как ключи
провайдеров) и больше не показывается. Потеряли — сделайте `rotate`.

Требования к URL: HTTPS; приватные и loopback-адреса запрещены; DNS проверяется на
публичный адрес; редиректы запрещены при доставке. Для self-hosted установки, которой нужно
ходить во внутреннюю сеть, есть осознанный выключатель
`REMO_WEBHOOK_ALLOW_PRIVATE=1` (по умолчанию выключен).

Без `REMO_KEK` (32 байта, base64) настроить вебхук нельзя: сервер отвечает
`409 WEBHOOK_LOCKED`. Уже настроенный вебхук при потере KEK не «теряется молча» — доставки
падают и уходят в DLQ, пока ключ не вернут.

## Если эндпоинт не настроен

События всё равно создаются (их пишет команда), но дренаж помечает их опубликованными, не
отправляя: получателя нет. Очередь не растёт бесконечно у тех, кто вебхук не включал.

## Записи агента

Записи агента (ADR-097) — такие же события: `board.item.created` с
`payload.objectType = "card"` для карточек и `board.connector.created` /
`board.connector.updated` для связей. `actor.type` в конверте — `"agent"`, `actor.id` — id
агента; человек, поставивший задачу, — в строке задачи, не в событии.

События пишутся по частям (chunk) сразу после применения и до сохранения прогресса. У
каждого есть ключ идемпотентности на стороне сервера (`change-set:<id>:<операция>:<вид>:<объект>`),
поэтому повторный прогон после сбоя не пришлёт то же действие дважды.

**Граница, которая осталась:** изменения и удаления существующих объектов и правки текста
событий не порождают — ни у человека, ни у агента. Не ждите `board.item.updated`.

## Транспорт и SSRF

Доставка идёт через общий безопасный клиент: HTTPS обязателен; на каждой попытке
резолвятся все адреса, приватные отклоняются, сокет привязывается к проверенному IP,
редиректы запрещены. `REMO_WEBHOOK_ALLOW_PRIVATE=1` — явное исключение для внутреннего
получателя; оно не отменяет HTTPS и привязку адреса (ADR-109, amendment 29.10.2026).
