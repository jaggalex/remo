# Текст v2: заголовки, списки, чек-листы, ссылки, вставка и Markdown

ТЗ к **ADR-252**, который дополняет ADR-024. Статус: предложено, 2026-11-20.

Перед работой прочитайте:
- `AGENTS.md`;
- ADR-024 (форматирование — пометки на символах в `Y.XmlText`);
- ADR-027 (подгонка размера текста под стикер);
- ADR-103 (ссылка объекта);
- ADR-176 (пределы текста);
- ADR-214–216 (рост фигуры под текст);
- `packages/doc/src/text.ts`, `packages/canvas/src/textLayout.ts`, `apps/web/src/richText.ts`, `apps/web/src/InlineEditor.tsx`.

## 0. Проблема и цель

**Сейчас:**
- модель хранит четыре пометки внутри строки: жирный, курсив, подчёркнутый, зачёркнутый;
- есть плашка B/I/U/S и ⌘B/⌘I/⌘U;
- вставка из буфера не обрабатывается: браузер вставляет в `contentEditable` чужой HTML
  (заголовки, списки, шрифты, цвета);
- `deltaFromDom` сохраняет только четыре пометки;
- строки из `<li>` и `<h1>` могут слиться: переносом считаются только `div`, `p` и `br`;
- после закрытия редактора на холсте нарисовано не то, что было видно при правке;
- Markdown (`**жирный**`, `- пункт`) вставляется символами.

**Цель.** Текст, за который не стыдно, без смены хранения и без внешнего редактора:
- **внутри строки:** жирный, курсив, подчёркнутый, зачёркнутый, код, ссылка;
- **строки:** обычная, заголовок 1, заголовок 2, маркированный список, нумерованный список,
  чек-лист; отступ списков — 3 уровня (0–2);
- **ввод:** Markdown-правила при наборе, сочетания клавиш, плашка;
- **вставка:** HTML (веб, Google Docs, Notion, Word) и Markdown (чаты с ИИ, GitHub)
  превращаются в эту разметку; ⌘⇧V вставляет без форматирования;
- **копирование из редактора:** HTML плюс Markdown в `text/plain`;
- **холст:** галочки чек-листа отмечаются кликом, ссылки открываются;
- **Markdown как формат обмена:** один парсер и один сериализатор для вставки, API,
  агентов и экспорта.

**Вне объёма** (каждое — отдельным решением, если понадобится):
- цвет и размер отдельных слов;
- выравнивание отдельных строк;
- цитаты и блоки кода в несколько строк;
- таблицы и изображения внутри текста;
- вложенность глубже трёх уровней;
- упоминания `@`.

## 1. Правила, которые нельзя нарушить

1. **Одно хранилище.** Текст остаётся `Y.Text` / `Y.XmlText` (ADR-024). Никакого второго
   представления: HTML в поле, Markdown в поле, `Y.XmlFragment`.
2. **Текст без новой разметки рисуется как раньше, байт в байт.** Пути «простой текст» и
   «только пометки» не меняются. Блочная раскладка включается, только когда в тексте есть
   хотя бы одна строка с блочным атрибутом.
3. **Что видно в редакторе, то и сохранится.** Всё, что попадает в редактор (вставка,
   ввод, команды), сначала проходит через белый список §3. В DOM редактора не бывает
   разметки, которую модель не хранит.
4. **Один парсер Markdown и один перевод HTML → дельта** в `packages/doc`. Ими пользуются
   web, sync, импорт и агенты.
5. **Ссылки — только `http:`, `https:`, `mailto:`.** Всё остальное удаляется при вставке, в
   `sanitize.ts` и при чтении документа.
6. **Совместная правка как сейчас:** правка символов сливается посимвольно, атрибуты
   разрешаются по правилу «последний записавший побеждает» на уровне атрибута.

## 2. Модель

### 2.1 Атрибуты (`packages/model/src/types.ts`)

```ts
/** Inline marks, on any character. */
export interface TextMarks {
  bold?: boolean;
  italic?: boolean;
  underline?: boolean;
  strike?: boolean;
  code?: boolean;              // new: inline code
  href?: string;               // new: link target; http(s) or mailto only
}

/** Line format, ONLY on the "\n" that ends a line (§2.2). */
export interface LineFormat {
  block?: "h1" | "h2" | "bullet" | "ordered" | "check";
  indent?: 1 | 2;              // absent = 0; lists only
  checked?: boolean;           // block === "check" only
}

export interface TextDeltaOp {
  insert: string;
  attributes?: TextMarks & LineFormat;
}
```

- **Почему `href`, а не `link`.** У объекта уже есть поле `link` (ADR-103, ссылка на URL или
  объект). Это разные вещи; одинаковое имя запутало бы `sanitize.ts` и плашку.
- **`code` и `href` можно совмещать** с остальными пометками. `code` выключает
  `underline` при отрисовке.

### 2.2 Где живёт формат строки

Формат строки хранится на символе `\n`, который **завершает** строку. Так делают Quill и
подобные редакторы, и `Y.XmlText` это уже поддерживает: атрибуты можно ставить на любой
символ.

- **Последняя строка** с блочным форматом получает завершающий `\n` с этим форматом. В
  простом тексте такой `\n` в конце **не считается пустой строкой**: высота, отрисовка,
  `plainOf` для имени (ADR-165) и поиск его отбрасывают. Последняя строка без формата
  завершающего `\n` не имеет, как сейчас.
- **На символах, кроме `\n`,** блочные атрибуты запрещены: `canonicalMarks` их снимает.
- **На `\n`** запрещены пометки внутри строки (`bold` на переносе смысла не имеет):
  `canonicalMarks` для `\n` оставляет только `LineFormat`.
- **Единая функция разбора** в `packages/doc/src/text.ts`:

```ts
export interface TextLine {
  runs: TextRun[];            // inline runs of this line, "\n" excluded
  block?: LineFormat["block"];
  indent: 0 | 1 | 2;
  checked: boolean;
  ordinal?: number;           // 1-based number for "ordered", computed (§2.4)
}
export function linesOf(delta: readonly TextDeltaOp[]): TextLine[];
```

Все потребители — отрисовка, высота, подгонка шрифта, редактор, Markdown, экспорт — читают
строки только через `linesOf`.

### 2.3 Что меняется в `packages/doc/src/text.ts`

- `canonicalMarks` → `canonicalAttributes(op)`: шесть пометок для обычных символов, три
  поля формата для `\n`. `href` нормализуется и проверяется (§1, правило 5); неверный —
  снимается.
- `marksKey` учитывает `code`, `href`, `block`, `indent`, `checked`.
- `insertionMarks` → `insertionAttributes`: все атрибуты явные (`null`, когда не заданы),
  чтобы ничего не наследовалось слева, как в ADR-024.
- `setWidgetDelta`: сравнение «общий префикс / общий суффикс» идёт по символам **и**
  атрибутам, как сейчас. Изменение только формата строки — это замена одного символа `\n`
  в середине, которая сливается с правками других людей.
- **Дешёвая операция формата строки:** новая функция
  `setLineFormat(board, id, lineIndex, format)`. Она делает `text.format(offsetOfNewline, 1,
  attrs)` без пересылки всей дельты. Ею пользуются плашка, сочетания клавиш и клик по
  галочке на холсте. Если нужного завершающего `\n` нет (последняя строка), он
  добавляется в той же транзакции.
- `withMaterializedText`: кроме `runs` материализует `lines` — **только если** хотя бы у
  одной строки есть `block` (правило 2). `Widget.lines?: TextLine[]`.
- `hasMarks(run)` учитывает `code` и `href`.

### 2.4 Нумерация

`ordinal` вычисляется в `linesOf`, в документе не хранится:
- подряд идущие строки `ordered` с одинаковым `indent` нумеруются с 1;
- строка с большим `indent` не прерывает нумерацию родителя;
- любая другая строка того же или меньшего уровня начинает нумерацию заново.

Хранимого «начать с N» нет (вне объёма).

### 2.5 Где разрешено

| Объект | Внутри строки | Строки (`block`) |
|---|---|---|
| `text` | всё | всё |
| `sticky_note`, `shape` | всё | всё |
| `connector` (подпись) | всё | нет: подпись в одну строку (ADR-041) |
| `card` | нет (как сейчас, ADR-024) | нет |

Разрешения задаются в таблице возможностей `kinds.ts` (`richBlocks: boolean`), а не
условиями по типу в коде.

### 2.6 Проверка и пределы

- `packages/model/src/sanitize.ts`: `validRun` → `validAttributes`; плюс проверка
  `Widget.lines`. Неверный `href` удаляется, `indent` вне 1–2 удаляется, `checked` без
  `check` удаляется.
- ADR-176: атрибуты не меняют предел числа символов. Длина `href` — не больше 2 048
  символов.

### 2.7 Совместимость

- **Старые комнаты** не меняются: у них нет новых атрибутов.
- **Старый клиент** в момент выкатки (вкладка не перезагружена): при правке он не знает
  новых атрибутов. Неизменённые символы сохраняют формат, пересозданная середина может
  его потерять. Окно короткое: клиент перезагружается при новой версии. Это записывается в
  ADR-252 как принятое ограничение. Дополнительно сервер шлёт `minClientVersion`, и
  `SyncLine` предлагает обновить страницу, если механизм уже есть. Если нет, вне объёма.
- **Бэкап** (`apps/sync/backup.mjs`): `textDeltas` уже переносят атрибуты как есть. Импорт
  и `seedFragmentText` (`packages/doc/src/clipboard.ts`) пропускают атрибуты через
  `canonicalAttributes`. Версия формата бэкапа не меняется: новые поля необязательны.
- **Проекция** (`widgets.content`, `apps/sync/project.mjs`): простой текст, как сейчас.
  Дополнительно `props.markdown` — сериализация §4, чтобы Read API и MCP могли отдавать
  структуру.

## 3. Белый список HTML ↔ дельта (`packages/doc/src/html.ts`, новый)

Одна пара функций: `deltaFromHtml(fragment)` и `htmlFromDelta(delta)`. В браузере `richText.ts`
использует их вместо своих `deltaToHtml` / `deltaFromDom`. Логика переезжает, а не
дублируется.

Разбор чужого HTML идёт через `DOMParser` в инертном документе (`text/html`): без скриптов,
без загрузки ресурсов, атрибуты `on*` не исполняются.

| Вход | Результат |
|---|---|
| `b`, `strong`, `font-weight` ≥ 600 | `bold`. **Исключение Google Docs:** `<b style="font-weight:normal" id="docs-internal-guid-…">` — не жирный |
| `i`, `em`, `font-style: italic` | `italic` |
| `u`, `text-decoration: underline` (если не ссылка) | `underline` |
| `s`, `del`, `strike`, `line-through` | `strike` |
| `code`, `kbd`, `samp`, шрифт `monospace` внутри строки | `code` |
| `a[href]` с разрешённой схемой | `href`; иначе только текст |
| `h1` | строка `h1` |
| `h2` … `h6`, строка целиком жирная и крупнее 1.3 em (Word) | строка `h2` |
| `ul > li` | `bullet`, `indent` = глубина вложенности − 1 (не больше 2) |
| `ol > li` | `ordered`, так же |
| `li` с `input[type=checkbox]`, GitHub `task-list-item`, Notion `to_do` | `check`, `checked` по флажку |
| `p`, `div`, `br`, `tr` | граница строки |
| `pre` | строки, каждая с `code` |
| `blockquote` | обычные строки |
| `td`, `th` | ячейки строки через « · » |
| `img`, `video`, `iframe`, `svg`, `style`, `script`, комментарии | отбрасываются |
| всё остальное | только текст |

- Пробелы нормализуются как в браузере: схлопываются, кроме `pre`.
- Неразрывный пробел остаётся.
- Пустые строки подряд сжимаются до одной.

`htmlFromDelta` строит HTML для редактора и для копирования:
- каждая строка — `<div data-block="…" data-indent="…" data-checked="…">` (в
  буфер — `h1`, `h2`, `ul/ol/li`);
- пометки — `b`, `i`, `u`, `s`, `code`, `a href rel="noopener noreferrer"`.

## 4. Markdown (`packages/doc/src/markdown.ts`, новый, без зависимостей)

Подмножество, ровно соответствующее модели:

| Markdown | Модель |
|---|---|
| `# ` / `## ` (и `###`… → `h2`) | `h1` / `h2` |
| `- `, `* `, `+ ` | `bullet` |
| `1. `, `1) ` | `ordered` |
| `- [ ] `, `- [x] `, `[ ] `, `[x] ` | `check` |
| 2 или 4 пробела, или Tab перед маркером | `indent` (не больше 2) |
| `**x**`, `__x__` | `bold` |
| `*x*`, `_x_` (не внутри слова) | `italic` |
| `~~x~~` | `strike` |
| `` `x` `` | `code` |
| `[текст](https://…)`, голый `https://…` | `href` |
| `> ` | обычная строка, без `> ` |
| блок ` ``` ` | строки с `code` |
| `\*` и подобные экранирования | символ как есть |

- `parseMarkdown(text) → TextDeltaOp[]` и `toMarkdown(delta) → string`. Круговой тест:
  `parseMarkdown(toMarkdown(d))` = `d` для любой дельты модели.
- **Когда вставка считается Markdown.** В `text/plain` нет `text/html`, и выполнено одно
  из:
  - есть строка, начинающаяся маркером списка, заголовка или чек-листа;
  - есть парные `**`, `~~` или обратные кавычки;
  - есть `[…](http…)`.

  Иначе — простой текст. ⌘⇧V всегда даёт простой текст.
- **Где используется:**
  - вставка (§6);
  - копирование из редактора (`text/plain` = Markdown);
  - Read API и проекция (`props.markdown`);
  - API команд и MCP: поле `markdown` при создании и изменении текста — альтернатива
    `content`, парсится в sync тем же модулем;
  - агенты: шаги плана, которые создают текст, могут нести `markdown`. Включается
    отдельным этапом (§11), раньше агенты пишут как сейчас.

## 5. Редактор (`InlineEditor.tsx`, `richText.ts`)

### 5.1 DOM

- Редактор всегда держит **строку = один `div`**. При открытии он заполняется из
  `htmlFromDelta`. После ввода `deltaFromDom` читает строки по `div` (`br` внутри `div` —
  тоже граница строки, `div` без содержимого — пустая строка).
- Вид строк в редакторе совпадает с отрисовкой §7: те же отступы, маркеры через CSS
  `::before`, размеры заголовков, галочка. Стили — в
  `apps/web/src/styles` из токенов, без литералов.
- Пометки внутри строки по-прежнему через `document.execCommand` (как сейчас). Если
  `execCommand` нет, пометка не ставится, ввод работает.
- Формат строки ставится **не** через `execCommand`: функция `setLineBlock(format)` находит
  `div` строк, затронутых выделением, и меняет их `data-*`. Затем вызывается `commit()`.

### 5.2 Markdown-правила при наборе

Срабатывают в начале строки по пробелу:

| Набрано | Строка становится |
|---|---|
| `-`, `*`, `+` | маркированный список |
| `1.`, `1)` | нумерованный |
| `[]`, `[ ]` | чек-лист |
| `[x]` | отмеченный пункт чек-листа |
| `#` / `##` | заголовок 1 / 2 |

Срабатывают при вводе закрывающего символа:
- `**текст**` → жирный;
- `*текст*` или `_текст_` → курсив;
- `~~текст~~` → зачёркнутый;
- `` `текст` `` → код.

**Отмена правила:** Backspace сразу после срабатывания возвращает набранные символы как
текст. Так ведут себя Notion, Google Docs и Miro.

Правила включены по умолчанию (решение владельца продукта, §13) и выключаются в
настройках (`settings.markdownShortcuts`).

### 5.3 Клавиши

| Клавиши | Действие |
|---|---|
| ⌘B / ⌘I / ⌘U | как сейчас |
| ⌘⇧X | зачёркнутый |
| ⌘E | код |
| ⌘K | ссылка: окно с полем адреса над выделением; на ссылке — изменить или убрать |
| ⌘⌥1 / ⌘⌥2 / ⌘⌥0 | заголовок 1 / 2 / обычная строка |
| ⌘⇧8 / ⌘⇧7 / ⌘⇧9 | маркированный / нумерованный / чек-лист (повтор снимает) |
| ⌘\ | очистить форматирование выделения (пометки и формат строк) |
| ⌘⇧V | вставить без форматирования |
| ⌘Enter на строке чек-листа | отметить или снять галочку |
| Enter в пункте списка | новый пункт того же типа и уровня; в пустом пункте — выход из списка (строка становится обычной) |
| Enter в конце заголовка | следующая строка — обычная |
| Backspace в начале пункта | сначала снимает уровень отступа, потом формат строки, потом склеивает с предыдущей |
| Tab / ⇧Tab **в строке списка** | уровень отступа +1 / −1 (0–2) |
| Tab / ⇧Tab **вне списка** | как сейчас: создать соседний объект (ADR-028) |

На Windows и Linux ⌘ — это Ctrl. Все сочетания добавляются в клавиатурную модель
`spec/design-system.md` §17 и в справку, с проверкой конфликтов с сочетаниями холста.

### 5.4 Вставка (`onPaste`)

1. `preventDefault()` всегда: браузер больше ничего не вставляет сам.
2. Если в буфере наш собственный JSON фрагмента (`clipboard.ts`), вставка объектов идёт как
   сейчас и не касается текста.
3. ⌘⇧V или `text/plain` без признаков Markdown → простой текст.
4. Есть `text/html` → `deltaFromHtml`.
5. Только `text/plain` с признаками Markdown (§4) → `parseMarkdown`.
6. Результат вставляется в позицию курсора с заменой выделения, через тот же
   `htmlFromDelta` → DOM → `commit()`.
7. **Предел:** если после вставки текст превысил бы ADR-176, вставляется сколько влезает и
   показывается уведомление «Вставлено N из M символов: в объекте больше не помещается».
8. Строки со своим форматом, вставленные в середину строки, разбивают её: правило любого
   редактора.

### 5.5 Копирование из редактора (`onCopy` / `onCut`)

В буфер кладутся `text/html` (`htmlFromDelta` выделения) и `text/plain` (`toMarkdown`
выделения). Вставка в Notion, Google Docs, Word или чат сохраняет структуру.

## 6. Плашка (`object-panel/StickyPanel.tsx`)

Состав для `text`, `sticky_note`, `shape`; для подписи коннектора — только внутристрочные
пометки:

```
[Аа ▾] │ B I U S │ • 1. ☑ │ 🔗 │ ⋯
```

- **«Аа ▾»** — меню `Menu` из `@remo/ui`: «Обычный текст», «Заголовок 1», «Заголовок 2», с
  подсказкой сочетаний. Отмечен формат строки с курсором; при смешанном выделении не
  отмечено ничего.
- **B I U S** — как сейчас. Состояние `selected` отражает выделение в режиме правки и весь
  текст вне его (как сейчас).
- **• 1. ☑** — переключатели формата строки. Вне режима правки применяются ко всем строкам
  объекта.
- **🔗** — окно ссылки (§5.3, ⌘K). Вне режима правки неактивна с подсказкой «Выделите текст
  в режиме правки».
- **«⋯»:** «Код», «Отступ +», «Отступ −», «Очистить форматирование».
- Иконки — из набора REMO (`packages/ui/src/icons`). Недостающие (`list-bullet`,
  `list-ordered`, `list-check`, `heading`, `link`, `code`, `clear-format`) рисуются в его
  сетке 24/16 и добавляются по процедуре дизайн-системы.
- Ширина плашки растёт. Константы `NOTE_BAR_HALF`, `TEXT_BAR_HALF` и `SHAPE_BAR_HALF` в
  `floatingTargets.ts` пересчитываются. На ширине 900 px и на телефоне лишнее уходит в
  «⋯» (ADR-236, `spec/design-system.md` §18).

## 7. Отрисовка (`packages/canvas`)

Новый модуль `textBlocks.ts` (раскладка) плюс изменения в `textPaint.ts`. Если у объекта нет
`lines`, работает старый путь (правило 2).

**Геометрия.** `em` — текущий размер шрифта объекта (явный или подобранный, ADR-027):
- **Заголовки:** h1 — 1.5 em, жирность 600; h2 — 1.25 em, жирность 600. Межстрочный
  интервал 1.25 от размера строки. Над заголовком (кроме первой строки) — 0.4 em, под ним
  — 0.2 em.
- **Отступ уровня:** 1.5 em на уровень.
- **Маркер списка:** `•` на уровне 0, `◦` на 1, `▪` на 2, в колонке шириной 1.25 em.
- **Номер:** `{ordinal}.`, выравнивание по правому краю колонки. Ширина колонки — по
  самому широкому номеру в группе (`tabular-nums`).
- **Галочка:** квадрат 0.8 em со скруглением `radius-xs` и контуром 1.5 чернилами; у
  отмеченной — заливка чернилами и белая «✓». Текст отмеченного пункта — цветом
  `text-muted` и зачёркнутый. На бумаге — `sticker-ink` с прозрачностью 55%.
- **Перенос строки** продолжается с отступом текста, а не маркера (висячий отступ).
- **Код в строке:** моноширинный `font-mono` 0.92 em, подложка `alpha-ink-14`, скругление
  `radius-xs`, поле 0.15 em.
- **Ссылка:** цвет `text-accent`, подчёркивание 1 px. На бумаге (стикер) — `sticker-ink` с
  подчёркиванием, чтобы не нарушать правило «содержимое не перекрашивается»
  (README REMO 2.0).

**Высота и подгонка:**
- `stickyHeightFor`, `runsHeightFor`, `fitNoteFont`, `noteFontSizeFor`, `textClipped`
  получают версию для строк (`linesHeightFor` и т. п.) и выбирают её, когда есть `lines`;
- подгонка ADR-027 подбирает `em` так, чтобы влезли все строки с их размерами и отступами;
- рост фигуры ADR-214–216 и рост текста по высоте — по тем же функциям.

**Хит-тест** — новая функция `textHitAt(widget, point) → { kind: "checkbox", line } | { kind:
"link", href, range } | null` в `textBlocks.ts`, по той же раскладке.

**Экспорт PNG/PDF** (`exportRender.ts`) идёт через тот же painter: отдельной работы нет,
только эталоны.

## 8. Действия на холсте (вне режима правки)

- **Галочка.** Клик по ней переключает `checked` (`setLineFormat`). Это одна команда с
  проверкой права `board.edit`, один шаг отмены, запись в журнал по правилу 4
  `AGENTS.md`. У зрителя курсор не меняется и клик ничего не делает. На заблокированном
  объекте клик не работает.
- **Ссылка.**
  - Наведение показывает подсказку с адресом (`Tooltip`).
  - ⌘/Ctrl+клик открывает в новой вкладке (`noopener,noreferrer`).
  - Обычный клик выделяет объект, как сейчас. В плашке выделенного объекта появляется
    «Открыть ссылку» (если ссылка одна) или меню ссылок (если их несколько).
- **Двойной клик** входит в правку, как сейчас. Курсор ставится в место клика (если
  сейчас уже так, это сохраняется).

## 9. Доступность

- Доступное имя объекта — простой текст (как сейчас). Для чек-листа добавляется «Выполнено
  N из M».
- Кнопки плашки получают `aria-pressed` и подсказку с сочетанием клавиш.
- Окно ссылки: поле с подписью, Enter применяет, Esc закрывает и возвращает фокус.
- В редакторе строки списков получают `role="listitem"` внутри `role="list"`, галочки —
  `role="checkbox"` и `aria-checked`, чтобы программы чтения с экрана понимали структуру.

## 10. Тесты

**`packages/doc`:**
- `canonicalAttributes`: блочные атрибуты на обычном символе снимаются, пометки на `\n`
  снимаются, неверный `href` (`javascript:`, `data:`, длинный) снимается;
- `linesOf`:
  - строки, завершающий `\n` последней строки;
  - нумерация §2.4 (вложенность, прерывание);
  - пустые строки;
- `setWidgetDelta`:
  - смена формата строки — замена одного `\n`;
  - параллельная правка текста и формата двумя документами сходится;
  - текст без форматирования идёт простым путём как раньше (существующие тесты не
    меняются);
- `setLineFormat`: последняя строка без `\n` получает его в той же транзакции; один шаг
  отмены;
- `html.ts`: по одному тесту на каждую строку таблицы §3, плюс эталонные фрагменты буфера
  из Google Docs, Notion, Word, GitHub, ChatGPT и Claude (сохранить как фикстуры в
  `packages/doc/src/__fixtures__/paste/`);
- `markdown.ts`:
  - таблица §4;
  - круговой тест на случайных дельтах модели (свойства);
  - `_` внутри слова (`snake_case`) не курсив;
- `clipboard.ts` и бэкап: дельта с новыми атрибутами переживает копирование, импорт и экспорт.

**`packages/canvas`:**
- раскладка строк: отступы, висячий отступ, ширина колонки номеров, размеры заголовков;
- подгонка шрифта учитывает заголовки;
- `textHitAt` для галочки и ссылки;
- текст без `lines` даёт ту же раскладку, что до изменения (снимок).

**`apps/web`:**
- `deltaFromDom` / `htmlFromDelta`: круговой тест;
- правила Markdown и их отмена Backspace;
- клавиши §5.3, включая Tab в списке и вне его;
- вставка: каждый источник из фикстур даёт ожидаемую дельту; ⌘⇧V; предел ADR-176 с
  уведомлением.

**Браузер (`pnpm e2e`):**
1. Набрать «- пункт», Enter, «пункт 2», Tab, «вложенный» — на холсте список с вложенностью.
2. Вставить фикстуру Markdown из чата с ИИ: заголовок, список, жирный, ссылка — на холсте
   то же, что было видно в редакторе.
3. Вставить из Google Docs: нет ложного жирного.
4. ⌘⇧V вставляет простой текст.
5. Клик по галочке на холсте отмечает пункт; ⌘Z возвращает; зритель кликом ничего не
   меняет.
6. ⌘/Ctrl+клик по ссылке открывает вкладку; `javascript:` ссылка не появляется.
7. Двое правят один текст: один меняет список на нумерованный, другой печатает в этой же
   строке — оба изменения на месте.
8. Экспорт PNG комнаты со списками совпадает с эталоном.

**Визуальные эталоны** (`pnpm baselines`, светлая и тёмная тема):
- текст, стикер и фигура с каждым форматом строки;
- длинный перенос в списке;
- чек-лист отмеченный и нет;
- ссылка и код на бумаге и на белом;
- плашка в трёх состояниях;
- окно ссылки.

## 11. Этапы (каждый — отдельный PR, каждый проходит `pnpm verify`)

1. **Исправление вставки (до запуска, 1–2 дня).**
   - `onPaste` с белым списком только для четырёх существующих пометок: строки из
     `li`/`h*`/`p` больше не сливаются; Google Docs без ложного жирного.
   - Markdown → четыре пометки.
   - ⌘⇧V, ⌘⇧X, «Очистить форматирование».

   Это закрывает расхождение «видно одно — сохраняется другое».
2. **Модель.** §2: атрибуты, `canonicalAttributes`, `linesOf`, `setLineFormat`,
   `Widget.lines`, `sanitize.ts`, `kinds.ts`, совместимость, бэкап и буфер. Плюс
   ADR-252 → accepted.
3. **Отрисовка.** §7: `textBlocks.ts`, высота и подгонка, хит-тест, эталоны.
4. **Редактор.** §5.1–5.3: строки как `div`, формат строки, правила Markdown, клавиши.
5. **Плашка и холст.** §6, §8, доступность §9.
6. **Вставка и копирование целиком.** §3, §4, §5.4–5.5 с фикстурами.
7. **API и агенты.** Поле `markdown` в API команд и MCP, `props.markdown` в проекции;
   агенты могут писать Markdown в текст.
8. **Справка и гайд.** Страница «Оформление текста» в `guide/how-to`, сочетания в
   `content/help`, история изменений.

Этапы 2–5 дают видимый результат только вместе. Можно вести их в одной ветке и сливать по
очереди за флагом `settings.richBlocks` (по умолчанию выключен до этапа 5).

## 12. Приёмка

1. `pnpm verify --e2e` зелёный; визуальные эталоны §10 утверждены.
2. Комната, созданная в 0.4.1, после обновления выглядит пиксель в пиксель так же (сравнение
   эталонов на существующих шаблонах).
3. Вставка каждой фикстуры даёт на холсте ровно то, что было в редакторе до закрытия
   (снимок DOM редактора против снимка холста по тексту и формату строк).
4. Круговой тест Markdown проходит на 10 000 случайных дельтах.
5. Двое одновременно правят текст со списками 2 минуты в тестовом сценарии — документы
   сходятся.
6. В документе, бэкапе и проекции нет `href` со схемой, отличной от `http`, `https` и
   `mailto`.
7. Справка описывает все сочетания §5.3, и они не конфликтуют с сочетаниями холста.
