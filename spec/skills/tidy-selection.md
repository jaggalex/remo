# Скилл `tidy-selection@1`: выделение → ровные колонки

**Статус:** серверная часть, движок раскладки и UI реализованы (M5, 2 ноября 2026).
Браузерная приёмка — `e2e/tidy.spec.ts` на детерминированном провайдере
`REMO_AI_FAKE=plan`. **Связанные документы:** ADR-143 (выделение как источник и
tidy-план), ADR-142 (план, превью, применение, ⌘Z), ADR-110/ADR-141 (фреймы и
принадлежность), ADR-144 (`PLAN_TOO_LARGE` — отказ).

## 1. Задача

Человек выделяет объекты и нажимает «Упорядочить». Объекты встают ровными колонками:
сеткой, по префиксу (`US-2` раньше `US-10`), по типу или по смыслу, который назвала
модель. Размеры, тексты и связи не меняются; один ⌘Z возвращает всё. Если выделен
фрейм, раскладывается его содержимое **внутри** фрейма, а сам фрейм не двигается.

## 2. Манифест

```yaml
slug: tidy-selection
version: 1
name: Упорядочить выделение
description: Ровные колонки из выделения; блоки — только фреймами
required_capabilities: [board.read, board.edit]
tools: [read_selection, propose_plan]
risk: write
handler: builtin:tidy
input:
  intent: string                 # 3–2000 символов, обычно «Упорядочить выделение»
  selectionIds: [string]         # выделение; группы и фрейм раскрываются на сервере
  strategy: grid|prefix|type|meaning|auto
  origin: { x, y }
output:
  operations: [...]              # place_widgets + create_widgets
```

Скилл выбирается явным `slug` или интентом: «упорядочить», «приберись», «наведи
порядок», «разложи», `tidy up`, `arrange`. Явный `slug` главнее любого совпадения.
В селекторе скиллов показываются только совместимые с источником скиллы и «Авто».

## 3. Выделение как источник

- Группа раскрывается до участников; выбранный фрейм — до всего содержимого.
- Порядок — сверху вниз, затем слева направо.
- Пустые тексты и повторяющиеся предложения в текст для модели не попадают; объекты
  при этом остаются в раскладке.
- Связи попадают в источник, только если выбраны оба конца.
- Лимиты: 50 объектов и 20 000 символов; хвост обрезается по границе и задача
  помечается `SELECTION_TRUNCATED`.

## 4. Операции и раскладка

`place_widgets` двигает **существующие** id: `{id, x, y, parentRef?}`. Он не несёт
размер, текст или стиль. `create_widgets` создаёт фреймы-блоки. `create_group` не
существует: блок — это видимый фрейм, а не служебная группа.

| Стратегия | Что получается |
|---|---|
| `grid` | Сетка без фреймов; размеры сохраняются |
| `prefix` | Колонка-фрейм на каждый префикс, натуральный порядок внутри |
| `type` | Колонка-фрейм на каждый тип |
| `meaning` | Блоки с метками модели; объекты, которых модель не назвала, — в «Прочее» |
| `auto` | `prefix`, если префиксы есть у большинства; иначе `type` |

Блок: заголовок, отступы 24, зазор 32, объекты столбиком. Чужой объект не двигается —
блок сдвигается вниз. Если содержимое не помещается во фрейм при текущем размере,
план отклоняется `TIDY_DOES_NOT_FIT`: фрейм не растягивается. Закреплённые объекты
пропускаются с предупреждением `TIDY_LOCKED_SKIPPED`.

## 5. Модель — только смысл

При наличии провайдера runner просит `{strategy, blocks: [{label, ids}]}`. Модель не
возвращает координаты. Неизвестный ключ, чужой id, разметка или пустой список —
повод не для отказа задачи, а для детерминированной раскладки и предупреждения
`TIDY_CLASSIFICATION_IGNORED`. Без ключа или при ошибке сети происходит то же самое.

## 6. Жизненный цикл

1. «Упорядочить» создаёт задачу `tidy-selection` для агента пользователя.
2. Runner читает выделение, при возможности спрашивает метки, считает раскладку и
   сохраняет план `proposed`; на комнате ничего не меняется.
3. Превью показывает «до/после», стратегию и предупреждения. Смена стратегии —
   `POST /agent-tasks/{id}/plan/relayout` (только для `proposed`): метки сохраняются,
   координаты пересчитываются, аудит `agent.plan.relayout`.
4. «Применить» → `approve` → одна локальная транзакция (`LOCAL_ORIGIN`) → `applied`.
   Один ⌘Z снимает и новые фреймы, и все перемещения.

## 7. Пределы и отказы

| Что | Предел / код |
|---|---|
| Объектов в упорядочивании | 50 (`PLAN_TOO_LARGE` при большем) |
| Символов в источнике | 20 000 (`SELECTION_TRUNCATED`) |
| Блоков | 12 |
| Чужой id | `OBJECT_NOT_ALLOWED` |
| Фрейм/связь как цель | `FRAME_NOT_PLACED` / `CONNECTOR_NOT_PLACED` |
| Карточка в канбане | `CARD_NOT_PLACED` |
| Не помещается во фрейм | `TIDY_DOES_NOT_FIT` |
| Закреплён | пропуск + `TIDY_LOCKED_SKIPPED` |

## 8. Приёмочные критерии

| ID | Given / When | Then |
|---|---|---|
| TIDY-01 | 5 заметок `US-1`…`US-5` вразброс | Одна колонка, общий x, натуральный порядок |
| TIDY-02 | ⌘Z после применения | Все объекты на прежних местах, фрейм исчез |
| TIDY-03 | Выбран фрейм | Содержимое внутри, фрейм не двигается, вложенных фреймов нет |
| TIDY-04 | Модель вернула метки | Два блока `Billing`/`Flow`, стратегия `meaning` |
| TIDY-05 | Модель вернула чужой id | Метки игнорируются, объект вне выделения не двигается |
| TIDY-06 | 201 объект | `PLAN_TOO_LARGE`, план не сохранён |
| TIDY-07 | Закреплённая заметка | Осталась на месте, предупреждение в превью |
| TIDY-08 | Две вкладки | Вторая не может сменить стратегию уже одобренного плана |
