# Продуктовые метрики

Нормативное дополнение к ADR-082. Здесь — определения KPI и то, какие факты продукт
обязан эмитить, чтобы KPI можно было посчитать. Формулы живут в SQL/дашбордах, а не в
коде экрана: продукт эмитит **факты**, метрики из них выводятся.

## Принципы

- События типизированы в `packages/metrics`; новое событие добавляется в
  `METRIC_CATALOG` один раз.
- В событии нет текста комнаты, имён, email, IP и User-Agent. Только UUID и скалярные
  свойства.
- Sink по умолчанию выключен. Включается `REMO_METRICS_DATABASE_URL`; база
  `remo_metrics` отдельная, не продуктовая и не аудит.
- MAU/DAU считаются по аутентифицированным `actor_id`; агенты и посетители по ссылке —
  отдельные `actor_type` и в MAU не входят.

## Определения

**Activation Rate.** Доля новых организаций, достигших первого полезного
результата за 7 дней, среди всех, у кого есть полное 7-дневное окно наблюдения:

```
activated_7d / new_orgs_with_complete_window * 100
```

- Событие старта: `org.created` (`props.source`).
- Активация: комната с ≥ 3 объектами и подтверждённым сохранением —
  `board.saved { objectCount >= 3 }`; событие `activation.first_value { kind: "solo" }`
  эмитится один раз на организацию. В metrics-БД это обеспечивает partial unique
  index по `org_id` для этого события, поэтому повторные сохранения не создают
  дублей.
- Организации младше 7 дней в знаменатель не входят: иначе метрика занижается.
- Окно (7 дней) — параметр отчёта, а не константа продукта.

**Time to First Value.** От `org.created` до первого `activation.first_value`.
Показывать **медиану и p90**, не среднее. Рядом всегда Activation Rate: быстрое
меньшинство не должно скрывать медленное большинство.

**Onboarding Completion.** Обязательной настройки в remo нет; это опциональная
воронка: `org.created` → `board.created` → `object.created` (≥3) → `board.saved`.
Событие `onboarding.step { step }` фиксирует шаг; завершение — все шаги. Если
появится обязательная настройка, шаги и правило completion добавляются в каталог.

**Воронка первого сценария.** `board.created` → `object.created` (3 разных объекта) →
`board.saved` → `connector.created` или `share.invited`. Каждый шаг — доля от
предыдущего и от старта; разрыв показывает, где теряются новые пользователи.

**Regular value.** Организация с ≥ 3 value days за 28 дней. Value day = `board.saved`
+ (`object.created` / `connector.created` / `agent.task.finished {status: applied}`)
или совместная правка. Логин сам по себе value day не делает.

**Удержание по когортам.** Когорта — `org.created` по неделе/месяцу; активность —
любой value day в периоде. Считается по организациям, не по отдельным людям.

**Успешность сценариев.** `scenario.started` и `scenario.completed` с
`scenarioId`, `outcome`, `durationMs`, `failureReason`. Ключевые сценарии: создать
комнату, добавить объект, связать объекты, пригласить, изменить роль, включить ссылку,
запустить агента, экспорт (когда появится). Формула: completed / started по сценарию.

**AI: качество и стоимость.** `agent.task.finished { status, skill, actions, costUsd,
seconds }`. Качество в MVP — доля `applied` против `failed/cancelled`; стоимость —
`costUsd` на успешно применённую задачу. Субъективная оценка результата — позже;
LLM-судья в MVP не используется.

**MAU/DAU.** Уникальные `actor_id` с хотя бы одним value event за день/месяц;
событие входа само по себе не активность. Агенты (`actor_type=agent`) и посетители
(`visitor`) исключены.

**Конверсия в оплату, GRR, NRR.** Не считаются: биллинга нет. События `billing.*`
зарезервированы; цифры не публикуются до появления источника MRR.

## Какие события нужны сейчас

| Событие | Где | Зачем |
|---|---|---|
| `org.created` | регистрация | знаменатель активации и когорты |
| `session.started` | вход/регистрация | DAU/MAU без подмены активностью |
| `board.created` | создание комнаты | воронка |
| `object.created` | создание объекта | воронка, value day |
| `board.saved` | ack сохранения (сервер после записи) | активация, value day |
| `connector.created` | создание связи | первый сценарий |
| `share.invited`, `role.changed`, `link.enabled`, `link.security` | этап 2 | доступ и ссылка |
| `board.trashed`, `board.restored`, `board.duplicated` | этап 2 | корзина и копия |
| `agent.task.finished` | раннер | AI-качество/стоимость |
| `scenario.started/completed` | сценарии | успешность |
| `help.opened/search` | помощь | качество помощи; без текста запроса |
| `billing.*` | будущий биллинг | конверсия/GRR/NRR, пока не считаются |

## Отчёты

- Activation Rate + TTFV (median/p90) — по неделям.
- Воронка первого сценария — по когортам.
- Regular value и retention — по организациям.
- Scenario success — по сценариям и версиям приложения.
- AI quality/cost — по скиллам и моделям.

Отчёты — SQL-вьюхи над `metrics_events`; отдельного сервиса и обязательного AI-чата
нет.
