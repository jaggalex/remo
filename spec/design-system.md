# Дизайн-система REMO: техническое задание

**Версия:** 1.0.
**Дата:** 26 октября 2026.
**Основание:** ADR-078 (дизайн-система как пакет), ADR-124 (примитивы из `@remo/ui`),
ADR-127/140/147 (палитра и именованные цвета), ADR-139 (слои). Это правила, токены,
компоненты и состояния, по которым новые экраны собираются без дизайнера.


## 1. Задача

Собрать переиспользуемую систему для **desktop-first B2B** продукта с холстом, русским
интерфейсом и плотными панелями управления, чтобы:

1. новые экраны (доски, шаринг, агенты, журналы) собирались из готовых компонентов;
2. визуальные решения принимались один раз, а не в каждом диалоге;
3. AI-агент мог сгенерировать экран по спецификации компонента, не изобретая стиль;
4. состояния (read-only, offline, revoked, locked, denied) были частью системы, а не
   локальными заплатками.

**Почему сейчас:** 2 942 строки CSS в одном файле и 18 CSS-переменных без семантического
слоя; 22 компонента в `apps/web/src` уже дублируют кнопки, поля и панели. Дальше это
дешевле не станет.

## 2. Границы

**Входит:** токены, типографика, цвет и темы, плотность, сетка и отступы, иконки
(набор), компоненты и их состояния, паттерны экранов, канвас-специфика (курсоры,
выделение, floating bars), доступность, локализация, каталог, версионирование.

**Не входит:** маркетинговый сайт, мобильные приложения, фирменный логотип и иллюстрации,
анимационный брендинг, тёмная тема в v1 (закладываем токены, но не отгружаем), звук.

**Не переносим из Miro:** логотип, палитру как есть, скругления и тени как есть,
структуру навигации (у нас нет Spaces), «визитную карточку» продукта, туры и онбординг.

## 3. Принципы (выведены из наблюдений, а не из вкуса)

Каждый принцип: задача → наблюдение в референсе → что сохраняем → что меняем → как
проверяем.

**П1. Рабочая поверхность тише управления.**
Холст — самый большой и самый спокойный объект; панели — белые, с тонкой границей и
мягкой тенью. Наблюдение: `F11-public-link/owner-link-security.png`,
`F04-bulk-paste/paste-as-dialog.png`. Сохраняем: один акцентный цвет, низкая хрома
фона. Меняем: у нас канвас-фон чуть теплее, акцент — свой. Проверка: на скриншоте
экрана «доска + диалог» взгляд сначала падает на содержимое, а не на панель.

**П2. Один акцент = одно действие.**
В любом диалоге ровно одна primary-кнопка; destructive — отдельным цветом и всегда
справа/с подтверждением. Наблюдение: `F13-vote-budget/visitor-1-vote-left.png`
(«Start» единственная тёмная), `F11-public-link/owner-link-security.png`.
Проверка: в компоненте `Dialog` больше одной primary-кнопки быть не может — это
проверяется линтером разметки.

**П3. Плотно, но с воздухом на границах групп.**
Элементы управления — 28–32 px, текст 13–14 px, расстояния внутри группы меньше, чем
между группами (правило близости). Наблюдение: топбар и меню Miro
(`F04-bulk-paste/paste-as-dialog.png`, `F09-frame-delete/after-frame-delete.png`).
Проверка: в макете любой панели расстояние между группами ≥ 2× внутригруппового.

**П4. Состояние — это текст, а не только цвет.**
Read-only, offline, revoked, locked, denied всегда называются словами и попадают в
`aria-live`. Наблюдение: Miro показывает «Access revoked — Sharing settings for this
board have changed» (`F11-revoke-timing`), но **не** показывает офлайн/сохранение
(`F05-reconnect-save`). Сохраняем первое, исправляем второе.

**П5. Данные и управление разделены.**
Содержимое (холст, таблица, журнал) не смешивается с управлением (панели, меню):
управление живёт в шапке/инспекторе, данные — в рабочей области. Наблюдение:
`F01-spaces-nav/boards-list-columns.png` (таблица), `F10-comment-pin/comment-posted.png`
(тред сбоку от содержимого).

**П6. Деструктивное отличается формой, а не оттенком.**
Удаление — отдельный пункт меню, красный текст, подтверждение с числом объектов.
Наблюдение: Miro ставит `Delete` рядом с `Lock` в контекстном меню
(`F03-lock`), предупреждает о потере доступа («You and your team will lose access»,
`F11-effective-access/member-can-change-team-role.png`). Сохраняем предупреждение,
разделяем пункты.

**П7. Система объясняет себя.**
Любое право и любое ограничение показываются с источником: «вы editor, потому что
команда PM», «ссылка выключена», «заблокировано Alex». Наблюдение: ни владелец, ни
участник Miro этого не видят (`F11-effective-access`) — это наше отличие и главный
принцип доверия к IAM.

## 4. Токены

Три уровня. Имена — `kebab-case`, уровень виден в префиксе. Значения живут **только** в
primitive-слое; компоненты ссылаются только на semantic/component.

```
tokens/
  primitive.css      # сырые значения: палитра, размеры, тайминги
  semantic.css       # роли: bg/surface/text/border/accent/state
  component.css      # точечные: button-height, dialog-padding, canvas-cursor
  themes/light.css   # (dark.css — задел, не отгружается в v1)
```

**Цвет.** Primitive: `neutral` — 12 шагов (`0, 25, 50, 100, 150, 200, 300, 400, 500,
600, 700, 800, 850, 900, 950`), цветные шкалы `accent`, `danger`, `success`, `warning` —
5–6 шагов (`50, 100, 300, 500, 600, 700`). Правило выбора: 50–150 — поверхности,
300–400 — границы и иконки, 500–700 — текст и акцент, 800–950 — тёмная тема.
Semantic (обязательный минимум):

| Роль | Назначение |
|---|---|
| `bg-canvas` | фон холста (не «серый», а именно канвас) |
| `bg-app` / `bg-panel` | рабочая поверхность приложения и панелей |
| `bg-raised` / `bg-overlay` | всплывающие меню, диалоги, тултипы |
| `text-primary` / `text-secondary` / `text-muted` / `text-inverse` | иерархия текста |
| `border-subtle` / `border-strong` / `border-focus` | границы и фокус |
| `accent` / `accent-hover` / `accent-soft` / `text-on-accent` | единственное действие |
| `danger` / `danger-soft` / `text-on-danger` | destructive |
| `state-success` / `state-warning` / `state-info` | статусы (не декор) |
| `selection-fill` / `selection-stroke` | выделение на холсте |
| `presence-1…6` | цвета курсоров участников |

Правила: контраст текста ≥ 4.5:1, крупного ≥ 3:1, `text-on-accent` ≥ 4.5:1 на
`accent`; цвет никогда не единственный носитель смысла (дублируется иконкой/текстом);
`accent` не используется для «просто красиво».

**Типографика.** Один семейный шрифт (Inter + системный fallback), шкала из 6 ролей:
`display 24/32`, `title 18/26`, `subtitle 15/22`, `body 14/20`, `label 13/18`,
`caption 12/16`. Вес: 400/500/600. Числа — табличные (`font-variant-numeric`) в
таблицах и журналах. Максимум 3 размера на экран.

**Пространство.** База 4 px, шаг 4: `space-1…12` (4…48). Компонентные отступы
(`control-padding-x = 12`, `dialog-padding = 20`, `panel-gutter = 16`) выводятся из базы,
но не подменяют её.

**Форма.** `radius-sm 6` (чипы, поля), `radius-md 10` (панели, карточки),
`radius-lg 14` (диалоги), `radius-pill` (статусы). Границы 1 px; тень — только у
всплывающего (`shadow-pop`) и парящих панелей (`shadow-bar`).

**Движение.** `dur-1 120ms` (hover/focus), `dur-2 180ms` (появление меню),
`ease-out`. Всё, что двигается на холсте (zoom/pan), — без анимации. При
`prefers-reduced-motion` длительности → 0.

**Плотность.** Два размера элементов: `compact 28` (панели, меню, тулбары) и
`default 32` (формы, диалоги). Переключение — на уровне токенов, не «руками» в
компонентах.

## 5. Компоненты

Каждый компонент описывается одинаково: анатомия → состояния → размеры → поведение →
a11y → где применяется. Ниже — обязательный инвентарь v1, привязанный к текущему коду.

**Примитивы**
`Button` (primary/secondary/ghost/danger; sizes 28/32; loading; icon-only) ·
`IconButton` · `Link` · `Input` (text/password/search; error/success; prefix/suffix) ·
`Textarea` · `Select` (single, native-first) · `Checkbox` · `Radio` · `Switch` ·
`Avatar` (initials + цвет) · `Badge`/`Chip` (status, removable, counter) · `Tooltip` ·
`Spinner` · `Skeleton` · `Kbd` · `Separator`.

**Контейнеры**
`Dialog` (sm 420 / md 560 / lg 720; header/body/footer; dismissable; focus trap) ·
`Popover` · `Menu` (item, checkbox, radio, separator, danger) · `ContextMenu` ·
`Panel` (right inspector 276; header/scroll) · `Tabs` · `Table` (sticky header, zebra off,
row actions) · `List` (two-line, meta, actions) · `Toast` (info/success/danger, 5 s,
`aria-live`) · `EmptyState` · `Banner` (inline, closable) ·
`Confirm Dialog` (с числом затронутых объектов).

**Продуктовые (поверх примитивов)**
`TopBar` (название доски, инструменты, presence, Share, статус) ·
`Toolbar` (инструменты создания; vertical rail) ·
`FloatingBar` (выделение: закреплённый набор действий) ·
`Inspector` (свойства, счётчики, история) ·
`ShareDialog` (роли и **источник** роли, ссылка с паролем/сроком, копирование) ·
`OrgDialog` (People/Agents/Audit) ·
`AgentDialog` (задача, скилл, бюджет, область) ·
`JournalList` (AI-журнал: seq, модель, токены, стоимость) ·
`CanvasCursor/Presence` · `CanvasSelection` · `CanvasTooltip`.

**Состояния — обязательны для каждого интерактивного компонента:**
`default`, `hover`, `active`, `focus-visible`, `disabled`, `loading`, `error`,
`read-only`, `selected`. Компонент без всех девяти не принимается.

**Канвас-специфика (наше отличие от «веб-системы»):**
курсор участника (цвет + имя, затухание 2 с), выделение (заливка 8 % + обводка 1.5 px,
внутренние ручки 8 px), hover-подсветка объекта, «чужой» объект (кто редактирует),
заблокированный объект (замок + «locked by …»), тултип с горячей клавишей, состояние
«слежу за Alex» (рамка + подпись), контекстное меню правого клика.


### 5.1 Объекты холста (обязательный блок, не «частный случай»)

Холст — половина интерфейса, и его элементы живут по своим правилам. Их нельзя
растворять в общих компонентах: у них другие состояния и другой носитель смысла
(геометрия, а не текст).

**Стикер.** Анатомия: заливка (палитра из 7 цветов: нейтральный, жёлтый, зелёный,
голубой, розовый, фиолетовый, оранжевый), текст 14/20 с автопереносом, автор, реакции.
Состояния: `default`, `hover` (тонкая тень + подсветка), `selected` (обводка 1.5 px +
8 ручек), `editing` (каретка, панель форматирования), `locked`, `read-only`, `remote`
(кто-то печатает — бейдж с именем), `with-reactions`, `with-votes` (бейдж-счётчик).
Ограничения — **наше решение, а не факт о Miro**: лимит 6 000 символов, дальше ввод
блокируется сообщением «достигнут лимит». Длинный текст переносится, кегль остаётся 14;
после 12 строк появляется индикатор «текст длинный», объект растёт вниз. Уменьшение кегля
не применяем: на проекторе это ухудшает читаемость. Поведение Miro на лимите не
проверено (`F04-tags-limits` — todo) и на решение не влияет.

**Связь (connector).** Анатомия: линия, наконечник, точки привязки (anchors), подпись
(опционально). Типы: `line`, `arrow`, `elbow`, `block` — это свойство одного объекта,
не четыре разных. Состояния: `default`, `hover` (толще + точки-порты на концах),
`selected`, `editing-label`, `pending` (режим создания: превью от источника к курсору).
Состояния «разорванная связь» нет: связь удаляется вместе с объектом-концом.
Правила: конец связи — **ссылка на объект и порт**, а не координата; при удалении
объекта удаляются и его связи (ADR-077); вставка узла — одна команда с превью (ADR-072).

**Якоря (ports).** Визуально: 8 точек по периметру фигуры (4 стороны + 4 угла),
появляются на hover, увеличиваются при наведении, «прилипают» в радиусе 12 px.
Состояния: `hidden`, `visible`, `hot` (под курсором), `connected` (занят).
Правило: якорь — это адрес, а не украшение; он должен быть доступен с клавиатуры
(циклический обход портов выбранного объекта по `Tab`).

**Фрейм.** Заголовок слева сверху (13/18, полужирный), граница 1 px, заливка фона
опциональна, номер порядка для презентации, состояния `hidden`, `selected`,
`drop-target` (в него перетаскивают объект), `clipped` (объект выходит за границы).
Правило: удаление фрейма не удаляет содержимое (ADR-070) — это должно быть видно в
подтверждении.

**Выделение и манипуляции.** Маркиза (заливка 8 % + обводка), ручки 8 px с зоной
захвата 12 px, курсоры изменения размера, поворот (если включаем — отдельная ручка,
иначе не показываем), направляющие выравнивания (1 px, акцент 40 %), сетка (точки/линии,
шаг 20 px, отключаемая), линейки — не входят в v1.

**Навигация по холсту.** Зум-контролы (−, %, +, fit), мини-карта (прямоугольник
вьюпорта, без миниатюр объектов), HUD координат, кнопка «показать всех», индикатор
следования за участником (рамка + подпись «Слежу за Alex»).

**Presence.** Курсор: стрелка + имя на плашке цвета участника, затухание 2 с,
6 фиксированных цветов (контраст к обоим фонам). Состояния: `idle`, `moving`,
`typing` (в объекте), `following you`.

**Оверлеи на холсте.** Пин комментария (кружок 24 px + хвост), бейдж реакций,
счётчик голосов, виджет таймера, карточка голосования, бейдж «locked by …»,
индикатор «read-only» у края доски.

## 6. Паттерны (проверяются на реальных экранах)

1. **Плотный диалог доступа** (Share): строка субъекта = кто + роль + **источник** +
   действия; публичная ссылка отдельным блоком с состоянием (выкл/пароль/срок) и
   предупреждением о последствиях.
2. **Инспектор справа**: свойства выбранного, счётчики, история; ничего
   редактируемого, что дублирует холст.
3. **Floating bar выделения**: не более **6** действий + `⋯` — предел, при котором
   панель не перекрывает выделение на ширине 1280 px. Проверка: при выделении объекта
   шириной 120 px панель выходит за его края не более чем на 40 px с каждой стороны.
4. **Статус синхронизации**: одно место в топбаре, три состояния (saved/pending/offline)
   словами, без спиннеров.
5. **Пустое состояние**: что это, зачем, одно действие, пример.
6. **Опасное действие**: подтверждение с числом («удалить 12 объектов»), undo в тосте
   там, где это возможно.

## 7. Доступность

- Клавиатура: всё достижимо, порядок логичный, `Esc` закрывает верхний слой, фокус
  возвращается туда, откуда пришёл; фокус-ловушка только в модальных диалогах.
- `:focus-visible` — 2 px `border-focus` + offset 2; никогда не убираем без замены.
- `aria-live="polite"` для статусов (saved/offline/revoked), `role="alert"` для ошибок.
- Иконка без текста → `aria-label`; декоративная → `aria-hidden`.
- Контраст проверяется в CI на токенах (скрипт `pnpm ds:contrast`), а не глазами.
- Кнопка не переносит текст; максимальная ширина подписи — 240 px. Если строка не
  влезает, сокращается **источник** (текст короче), а не компонент. Проверка: автотест
  каталога измеряет `scrollWidth <= clientWidth` для всех кнопок в RU и EN.

## 8. Локализация

RU — основной, EN — обязательный второй. Все строки в `i18n.tsx`, никаких подписей в
компонентах. Правила: не склеивать строки (`"{n} объектов"` → плюрализация), не
вмещать смысл в иконку, оставлять 30 % запаса по ширине для EN, даты и числа — через
`Intl` (уже есть `format.ts`).

## 9. Поставка

- Пакет `packages/ui` (`@remo/ui`): `tokens/`, `components/`, `patterns/`, `icons/`,
  `index.ts`. Стили — CSS-переменные + слои, без CSS-in-JS.
- **Каталог**: dev-маршрут `/__ds` (без Storybook в v1): каждый компонент во всех
  состояниях, с клавиатурной навигацией и переключателем плотности/темы. Каталог — часть
  Definition of Done, не «потом».
- **Версионирование**: semver пакета; ломающее изменение токена — major + запись в
  `packages/ui/CHANGELOG.md` + кодовмод (если возможно).
- **Тесты**: unit на логику (уже есть vitest), скриншот-тесты каталога на 3 ширины
  (том разрешено отложить до v0.2), проверка контраста в CI.
- **Миграция**: старые 18 переменных из `apps/web/src/styles.css` объявляются
  алиасами (`--ink → var(--text-primary)` и т.п.) на один релиз, затем удаляются.

## 10. Приёмка (проверяемое)

1. В каталоге `/__ds` есть **все** компоненты §5, каждый — во всех девяти состояниях.
2. Ни один компонент не задаёт цвет/размер литералом: правило обеспечивается
   `stylelint` (цветовые свойства — только `var(--…)`/`transparent`/`currentColor`) и
   тестом, который ищет `#hex` и `rgb(` в `packages/ui/src` (исключение — файл токенов).
3. `pnpm ds:contrast` проходит: все текстовые пары ≥ 4.5:1.
4. Клавиатурный прогон каталога: таб-порядок без ловушек, `Esc` закрывает, фокус
   возвращается.
5. Три эталона — (1) доска с выделением, курсором второго участника и открытым
   инспектором, (2) `Share` с включённой и выключенной ссылкой, (3) диалог агента с
   бюджетом и ошибкой валидации — собраны **только** из компонентов системы, каждый в
   двух темах и двух плотностях; лежат в `spec/ds-baselines/`.
6. Переключение плотности меняет высоту контролов 28↔32 без «прыжков» текста.
7. RU/EN: ни одна строка не обрезается в кнопках и табах на 1280 px.
8. Тёмная тема проходит **тот же** тест контраста, что светлая (все пары `text-*` на
   `bg-*` ≥ 4.5:1), и переключение не оставляет ни одного `var()` без значения.
9. Токен-файлы проходят линтер именования; дубликатов значений в semantic нет.
10. README пакета объясняет, как добавить компонент, за 1 экран.

## 11. Что выбросить из `spec/ds.md`

Исходный материал владельца (файл `ds.md`, в репозиторий не попал) — это **библиотека промптов для исследования референса**, а не ТЗ. Полезное,
что мы сохранили: формат «карточка паттерна», разделение
наблюдение/интерпретация/рекомендация, статус доказательства, требование показывать
систему на реальных экранах.

Что не переносим в ТЗ: роли и инструкции для агента-исследователя, порядок «сделай
скриншоты → опиши», этапность «направление → система → экраны» как процесс (у нас один
результат — система), рассуждения про «два визуальных направления» (направление одно,
оно ниже), общие ссылки на NN/g.

## 13. Визуальное направление (одно, для согласования)

**«Спокойный инструмент».** Направление описывается **именами токенов**, hex живёт
только в примитивах: холст `--bg-canvas`, панели `--bg-panel`, граница `--border-subtle`,
единственный акцент `--accent` (только действия и выделение), три уровня текста
`--text-primary/secondary/muted`, радиусы `--radius-sm/md/lg`, тень только у всплывающего
(`--shadow-pop`), Inter 13–14 px, контролы `--control-compact/default` (28/32), иконки
16/20 px штриховые. Никаких градиентов, «стеклянных» панелей и цветных заливок данных.

**Чего избегаем:** тяжёлых теней и «карточек в карточках», второго акцентного цвета,
цветных заливок статусов на всю строку, иконок без подписи в критичных действиях,
анимации на холсте.

## 16. Шаблон описания компонента

Обещанное «каждый компонент описывается одинаково» становится контрактом: без этих семи
полей компонент не принимается. Пример — кнопка.

```text
Компонент: Button
Назначение: единственное действие в контексте; не используется для навигации.
Анатомия: [иконка?] подпись [иконка?]; высота --button-height; паддинг --button-padding-x.
Варианты: primary | secondary | ghost | danger.
Размеры: default 32 (формы, диалоги), compact 28 (панели, меню, тулбар).
Состояния: default, hover, active, focus-visible, disabled, loading; selected — только
  для кнопок-переключателей; read-only — не применимо (кнопка скрывается или disabled).
Поведение: Enter/Space активируют; loading блокирует повторный клик и показывает спиннер;
  disabled не фокусируется, но читается скринридером как «недоступно».
A11y: role=button, aria-busy при loading, aria-label обязателен для icon-only.
Запрещено: две primary-кнопки в одном диалоге; перенос текста; цвет как единственный
  признак состояния.
```

Для компонентов холста добавляется восьмое поле: **геометрия** (размеры в единицах
доски, поведение при зуме, минимальный/максимальный размер).

## 17. Клавиатурная модель холста

Без этого раздела доступность холста не существует, а холст — основной экран.

| Действие | Клавиши | Ожидаемое поведение |
|---|---|---|
| войти в рельс | `Tab` из топбара | фокус на первом инструменте слева |
| войти в холст | `Tab` из рельса | фокус на первом объекте в порядке создания |
| обход объектов | `Tab` / `Shift+Tab` | по порядку создания; сфокусированный объект выделен |
| выделить несколько | `Shift` + стрелки обхода | мультивыделение без мыши |
| переместить | стрелки (1 px), `Shift`+стрелки (10 px) | без изменения порядка |
| изменить размер | `Alt`+стрелки | по 1 px за нажатие |
| войти в текст | `Enter` | каретка в конце текста; `Esc` возвращает к объекту |
| обход якорей | `Tab` внутри выбранного объекта | по 8 портам, `Enter` — начать связь, `Esc` — отменить |
| контекстное меню | `Shift+F10` | то же меню, что правый клик |
| выйти из холста | `Esc` дважды | фокус возвращается в топбар, туда, откуда пришли |
| статус | `aria-live` | «выбрано 3 объекта», «перемещено на 10 px» |

**Инструменты (ADR-119).** Нажатие создаёт объект сразу; «режима инструмента» нет, после
создания рельс снова показывает «Выбор». Клавиши не срабатывают в полях ввода, при
открытом редакторе и при открытом модальном слое; удержание клавиши не повторяет действие.

| Действие | Клавиши |
|---|---|
| снять выделение | `V` |
| стикер | `N` |
| пачка из пяти стикеров | `Shift+N` |
| текст | `T` |
| прямоугольник | `R` |
| эллипс | `O` |
| связь (нужны два выделенных объекта) | `L` |
| фрейм | `F` |
| карточка (нужен канбан) | `C` |
| отменить / повторить | `⌘Z` / `⇧⌘Z` |

## 18. Сетка, слои и размеры окна

- **Каркас:** топбар 52 px, вертикальный тулбар 48 px, инспектор `--inspector-width`
  (276 px), рабочая область — остальное. Минимальная ширина окна — 1024 px; ниже —
  горизонтальный скролл, панели не схлопываются.
- **Контрольные ширины:** 1280, 1440, 1920. На 1920 рабочая область не растягивает
  панели: инспектор остаётся 276 px, тулбар 48 px.
- **Слои:** снизу вверх — холст (`--z-canvas`: overlay-канвас, объекты рисуются на канве) →
  соцслой (`--z-canvas-overlay`: курсоры, пины комментариев, чипы голосования, реакции,
  слой размещения комментария) → плавающие панели (`--z-bar`: топбар, рельс, панели
  объектов, инспектор, панели досок и обсуждения, HUD, бейдж выделения) → меню и поповеры
  панелей (`--z-popover`: окна цвета, «Ещё», контекстное меню, тултипы, карточка объекта) →
  диалоги (`--z-dialog`) → уведомления (`--z-toast`). Панель всегда выше любого объекта и
  соцслоя; поповер панели — выше панели, из которой открыт. В компонентах только токен,
  не число. Внутри слоя порядок задаётся порядком в DOM, не `z-index`. Решение и
  проверки — ADR-139, `pnpm ui:check`.
- **Скроллинг:** скроллятся только панели и тела диалогов; страница не скроллится
  никогда (`overscroll-behavior: none` уже в продукте).
- **Диалоги:** ширина `sm 420 / md 560 / lg 720`, максимум `100vw - 40px`; высота —
  `100vh - 40px`; футер с действиями всегда виден (тело скроллится).

## 19. Глоссарий и контент-правила

**Термины (RU / EN):** доска / board · участник / member · гость / guest · посетитель
по ссылке / link visitor · команда / team · организация / organization · ссылка для всех
/ public link · агент / agent · задача агента / agent task · набор изменений / change set ·
журнал / journal.

**Правила текста:**

- Кнопки — глагол в инфинитиве без «пожалуйста»: «Удалить», «Скопировать ссылку».
- Ошибка = что случилось + что сделать: «Нет связи. Правки сохранены локально — они
  отправятся, когда соединение вернётся». Не «Ошибка 500».
- Запрет на «успешно» и «просто», на восклицательные знаки в системных сообщениях.
- Числа с существительными — через плюрализацию (`12 объектов`, `1 объект`), даты —
  `Intl.DateTimeFormat`, время — 24 ч.
- Имена людей и досок обрезаются по `ellipsis` с тултипом полного текста; в диалогах —
  перенос в две строки, дальше ellipsis.
- Тон: нейтральный, без оценок («хорошо», «плохо»), без обвинений («вы сделали»).

**Заголовки:** H2 — разделы диалога, H3 — группы внутри; в интерфейсе не больше двух
уровней заголовков на экран.
