# Изображения на холсте: хранение в S3/MinIO, загрузка, показ, дизайн и вёрстка

ТЗ к **ADR-249**. Статус: предложено, 2026-11-20. Связанные документы:
- `spec/billing.md` — квота хранилища по тарифу (`storageBytes`);
- `spec/design-system.md` — токены, компоненты, клавиатурная модель;
- ADR-071 и ADR-085 — формат бэкапа.

Перед работой прочитайте `AGENTS.md`, ADR-178 (RLS) и §5.1 «Объекты холста» в
`spec/design-system.md`.

## 0. Что есть сейчас и что делаем

- Тип `image` уже объявлен в модели (`packages/model/src/types.ts`, `kinds.ts`). Он может
  быть концом коннектора, входить в группу и попадать в раздел.
- Отрисовки, загрузки и хранения нет. В `schema.sql` прямо написано: «images come later».

**В объёме:**
1. Хранилище файлов: драйверы `disk` и `s3` (MinIO, Yandex Object Storage, Selectel,
   Hetzner, R2 и другие S3-совместимые).
2. Загрузка: кнопка на панели инструментов, перетаскивание файлов, вставка из буфера обмена.
3. Обработка: проверка, очистка метаданных, варианты размеров.
4. Показ на холсте: уровень детализации по масштабу, кеш, заглушки.
5. Объект «изображение»: размер с сохранением пропорций, замена, описание (alt), просмотр,
   скачивание оригинала.
6. Доступ, квота по тарифу, сборка мусора, экспорт PNG/PDF, бэкап и восстановление, копия
   комнаты.
7. Дизайн экранов и состояний (§9) и правила вёрстки (§10).

**Вне объёма v1:**
- обрезка (crop) и фильтры;
- SVG (опасен: скрипты внутри) и HEIC;
- вставка по URL с чужого сайта (риск SSRF; позже через `outbound.mjs`);
- создание изображений агентами;
- анимация GIF (показываем первый кадр);
- видео и PDF как объекты.

## 1. Правила, которые нельзя нарушить

1. **В документе комнаты (Yjs) нет байтов изображения.** Только ссылка на файл и метаданные.
   Предел размера комнаты (64 МиБ, `REMO_ROOM_MAX_BYTES`) не должен зависеть от картинок.
2. **Один путь чтения.** Браузер получает изображения только с адреса приложения
   (`/files/...`). Прямых ссылок на бакет у клиента нет.
   - Так права проверяются при каждом чтении.
   - Так CSP остаётся `img-src 'self' data: blob:`.
   - Так экспорт в PNG/PDF не «пачкает» canvas чужим источником.
3. **Право на файл = право на комнату.** Кто может открыть комнату (в том числе по публичной
   ссылке), тот видит её изображения. Кто не может — получает `404` (не `403`: не
   подтверждаем, что файл существует).
4. **Мы отдаём только то, что сами перекодировали.** Исходный файл пользователя никогда не
   отдаётся как `inline`. Оригинал скачивается только как вложение.
5. **Метаданные с личными данными удаляются.** EXIF, GPS, XMP и ICC-профили, кроме sRGB,
   вырезаются из всех вариантов. Оригинал хранится как загружен, но отдаётся только по явной
   кнопке «Скачать оригинал» и только тем, у кого есть право экспорта.
6. **Удаление объекта не удаляет файл сразу.** Иначе отмена (undo) и корзина вернут объект
   без картинки. Файлы удаляет сборка мусора (§5.4).
7. **Без S3 всё работает.** Драйвер `disk` — по умолчанию для self-host и разработки.

## 2. Хранилище

### 2.1 Драйверы

Файлы в `apps/sync`:

| Файл | Что внутри |
|---|---|
| `files-store.mjs` | интерфейс и выбор драйвера; `put(key, stream, meta)`, `get(key) → stream`, `head`, `delete`, `list(prefix)` |
| `files-disk.mjs` | драйвер `disk`: каталог `REMO_FILES_DIR` (по умолчанию `${REMO_DATA_DIR}/files`), запись через временный файл и `rename` |
| `files-s3.mjs` | драйвер `s3`: `@aws-sdk/client-s3`, `forcePathStyle` для MinIO, многочастная загрузка от 8 МиБ |

Ключ объекта: `orgs/{orgId}/files/{fileId}/{variant}`. Варианты: `original`, `w256`,
`w1024`, `w2048`. Ключ не содержит имени файла пользователя.

### 2.2 Конфигурация

| Переменная | Значение | По умолчанию |
|---|---|---|
| `REMO_FILES_DRIVER` | `disk` или `s3` | `disk` |
| `REMO_FILES_DIR` | каталог для `disk` | `${REMO_DATA_DIR}/files` |
| `REMO_S3_ENDPOINT` | `https://storage.yandexcloud.net`, `http://minio:9000` | — |
| `REMO_S3_REGION` | `ru-central1`, `eu-central-1`, `us-east-1` для MinIO | `us-east-1` |
| `REMO_S3_BUCKET` | имя бакета (приватного) | — |
| `REMO_S3_ACCESS_KEY_ID`, `REMO_S3_SECRET_ACCESS_KEY` | ключи с правами только на этот бакет | — |
| `REMO_S3_FORCE_PATH_STYLE` | `1` для MinIO | `0` |
| `REMO_FILES_MAX_BYTES` | предел одного файла | 20 МиБ |
| `REMO_FILES_MAX_PIXELS` | предел пикселей исходника | 50 млн |
| `REMO_FILES_PER_ROOM` | предел изображений в комнате | 500 |
| `REMO_FILES_CONCURRENCY` | параллельных обработок | 2 |

**Проверки при старте:** для `s3` — все переменные заданы, `HeadBucket` успешен, бакет не
публичный. Публичность проверяется анонимным `GET` ключа-маяка (`.remo-probe`): если
анонимное чтение удалось, сервис пишет громкую ошибку. Сам маяк не секретный и
перезаписывается при каждом старте.

Квота берётся из `entitlementsFor(org).limits.storageBytes`. При `REMO_BILLING=off` (и в
self-host) квоты нет — `storageBytes` = `null`; проверка `402` тогда не срабатывает, а лимит
изображений комнаты остаётся.

**Регион.** Российская установка хранит файлы в российском хранилище (152-ФЗ), европейская
— в европейском. Это свойство установки, как почта (ADR-246).

**Сервер.** MinIO для self-host добавляется отдельным сервисом в
`deploy/compose.production.yml` под профилем `files` (по умолчанию выключен), с томом и
созданием бакета при первом старте.

### 2.3 Резервное копирование файлов

`pnpm db:backup` файлы не копирует. Документация (`guide/admin/backup-restore`) описывает:
- для `disk` — копирование каталога;
- для `s3` — версионирование бакета и/или репликацию средствами провайдера (`mc mirror` для
  MinIO).

## 3. Данные

### 3.1 Таблица `files` (schema 25: таблица с 24, `security definer`-поиск организации `remo_file_org` с 25; после почты 21, биллинга 22 и биллинговых писем 23; RLS по `org_id`, ADR-178)

```sql
create table if not exists files (
  id uuid primary key default gen_random_uuid(),
  org_id uuid not null references orgs (id) on delete cascade,
  board_id text references boards (id) on delete set null,  -- the room it was uploaded to
  uploaded_by uuid references users (id) on delete set null,
  sha256 text not null,                  -- of the original bytes
  mime text not null check (mime in ('image/png','image/jpeg','image/webp','image/gif','image/avif')),
  bytes bigint not null,                 -- original
  stored_bytes bigint not null,          -- original + all variants: what the quota counts
  width integer not null, height integer not null,   -- after EXIF orientation
  dominant_color text,                   -- '#rrggbb', for the instant placeholder
  variants jsonb not null,               -- { "w256": { w, h, bytes }, ... }
  original_name text,                    -- shown on download only; never part of a key
  status text not null default 'ready' check (status in ('ready', 'deleted')),
  created_at timestamptz not null default now(),
  unreferenced_since timestamptz,        -- set by GC; cleared when referenced again
  deleted_at timestamptz
);
create index if not exists files_org_idx on files (org_id) where status = 'ready';
create unique index if not exists files_org_sha_idx on files (org_id, sha256) where status = 'ready';
```

`files` вносится в список tenant-таблиц `apps/sync/rls.sql` и в `rls-admin.mjs`; без этого
`--check` промолчит, а таблица останется без `FORCE ROW LEVEL SECURITY`.

**Дедупликация внутри организации.** Повторная загрузка того же файла (тот же `sha256`) в ту
же организацию возвращает существующий `fileId`. Квота не растёт. Между организациями
дедупликации нет: это утечка («у кого-то уже есть такой файл»).

### 3.2 Объект в документе комнаты

Используем существующий тип `image`. Поля в `props` (Yjs и проекция `widgets.props`):

```ts
interface ImageProps {
  fileId: string;          // files.id
  naturalWidth: number;    // pixels, for the aspect ratio and the "100%" size
  naturalHeight: number;
  dominantColor?: string;  // copied from files, so the placeholder needs no request
  alt?: string;            // description; up to 500 characters
}
```

- `width` и `height` объекта — размер на холсте в единицах доски.
- При создании: длинная сторона — не больше 480 единиц и не больше натурального размера.
- `kinds.ts`: у `image` `resizable: true`, ресайз только с сохранением пропорций (угловые
  ручки). Пропорции запирает новый признак `KindSpec` (`aspectLocked: true`), а не
  переопределение `Shift` в жестах: `Shift` остаётся общим переключателем свободного ресайза,
  `aspectLocked` его игнорирует.
- Агентный план (`agentPlan.ts`) изображения создавать не может, но может их перемещать и
  соединять, как сейчас.
- Поля хранятся плоско в `Widget`, как все остальные поля модели: контейнера `props` в
  `Widget` нет, `widgets.props` — колонка проекции, которую заполняет `project.mjs`. Второго
  способа хранить поля объекта не появляется.

## 4. Загрузка и обработка

### 4.1 API

Тело `multipart/form-data` читает новый потоковый ридер (рядом с `http-body.mjs`): предел
`REMO_FILES_MAX_BYTES`, обрезка даже при лживом `Content-Length`. `readJsonBody` для этого не
годится — он парсит JSON и держит тело в памяти.

| Метод и путь | Что делает |
|---|---|
| `POST /boards/:boardId/files` | `multipart/form-data`, поле `file`; необязательное поле `replace` — id объекта, чей файл заменяется: тогда вместо создания объекта выполняется команда `board.image.replace`. Право: `board.edit`. Ответ `201 { file: { id, width, height, dominantColor, variants } }` |
| `GET /files/:fileId/:variant` | `variant` ∈ `w256`, `w1024`, `w2048`. Право: просмотр комнаты, к которой относится объект (см. §4.3). Отдаёт WebP |
| `GET /files/:fileId/original` | скачивание оригинала как вложения. Право: `board.export` |
| `POST /boards/:boardId/files/:fileId/copy` | копия файла в организацию этой комнаты: вставка из комнаты другой организации и копия комнаты между организациями. Нужен доступ к обеим |

Коды: превышение размера — `413 TOO_LARGE`, неверная сигнатура — `415 BAD_TYPE`,
переполнение очереди — `503 SERVER_BUSY`, нет `board` или комната не использована — `404`.

`POST` проверяет порядок:
1. CSRF/Origin и права.
2. Rate limit: `upload:<userId>` — 60 в 10 минут.
3. `Content-Length` не больше `REMO_FILES_MAX_BYTES`. Поток обрезается на этом пределе,
   даже если заголовок соврал.
4. Тип файла по сигнатуре (магические байты), а не по расширению и не по `Content-Type`.
5. Квота организации (`entitlementsFor(org).limits.storageBytes`), лимит изображений
   комнаты — `402 PLAN_LIMIT` с `limit: "storage"` или `"room_images"`.
6. Обработка (§4.2), запись вариантов в хранилище, затем строка `files`. Если запись в
   хранилище упала, строки нет, а частично записанные ключи удаляет сборка мусора по
   префиксу.

### 4.2 Обработка

Через `sharp` (libvips). Это новая зависимость `apps/sync`, причина записана в ADR-249.

- `limitInputPixels = REMO_FILES_MAX_PIXELS` — защита от «декомпрессионной бомбы».
- `rotate()` по EXIF, затем удаление всех метаданных.
- Варианты `w256`, `w1024`, `w2048` по ширине, без увеличения, WebP качество 82. Вариант,
  который больше исходника, не создаётся: используется ближайший меньший.
- Прозрачность сохраняется.
- GIF — первый кадр.
- `dominant_color` — среднее по `w256`.
- Обработка идёт через очередь с ограничением параллельности (`REMO_FILES_CONCURRENCY`, по
  умолчанию 2), по образцу `hash-queue.mjs`. При переполнении — `503 SERVER_BUSY`.

### 4.3 Как чтение проверяет права

Файл принадлежит организации, а показывается в комнатах. Ссылка `/files/:id/w1024` не
знает, в какой комнате её открыли. Поэтому клиент передаёт контекст:

`GET /files/:fileId/w1024?board=<boardId>` (плюс токен публичной ссылки, если комната открыта
по ней, — тем же способом, что и для сокета).

Сервер проверяет:
1. право просмотра этой комнаты (`effective()` из `iam.mjs`);
2. что этот `fileId` действительно используется в комнате: строка в `widgets` с
   `type = 'image'` и `props->>'fileId' = :fileId`, либо `files.board_id = :boardId` для
   только что загруженного файла.

Проверка «файл используется в комнате» дополняется проверкой на командах `board.image.create`
и `board.image.replace`: `fileId` должен принадлежать организации комнаты и быть либо
загружен в неё (`files.board_id`), либо уже использоваться в ней. Без этого редактор мог бы
«легализовать» угаданный `fileId`, создав виджет, — инвариант 3 нарушился бы. Только проверки
чтения недостаточно.

Без пункта 2 любой участник одной комнаты мог бы читать чужие файлы организации, подбирая id.

`/files/:id/...` не попадает под `tenantOrgForRequest` (он знает только `/boards`, `/orgs`,
`/search`). Организация определяется `security definer`-функцией по `fileId` (по образцу
`boardOrg`), иначе запрос идёт без `app.org_id` и RLS вернёт 0 строк.

**Заголовки ответа:**
- `Content-Type: image/webp`, `X-Content-Type-Options: nosniff`;
- `Content-Security-Policy: default-src 'none'; sandbox`;
- `Cache-Control: private, max-age=31536000, immutable` (вариант по `fileId` неизменен);
- `ETag` = `sha256` варианта.

Оригинал отдаётся с `Content-Disposition: attachment; filename*=UTF-8''<имя>`.

Чтение из S3 идёт потоком, без буферизации целиком.

## 5. Жизнь файла

### 5.1 Вставка

Объект появляется в комнате **после** успешной загрузки, одной командой `createImage` (через
общий механизм команд и аудита, правило 4 `AGENTS.md`). До этого загрузку видит только
автор: локальная заглушка с прогрессом (§9.3). У других участников нет «полузагруженных»
объектов.

### 5.2 Копирование

- Копирование и вставка, дублирование и копия комнаты внутри одной организации переиспользуют
  тот же `fileId`.
- Вставка в комнату другой организации вызывает `POST .../copy`, файл копируется под новый
  `fileId` в целевой организации и учитывается в её квоте.
- Шаблоны с изображениями — вне объёма v1.

### 5.3 Бэкап и восстановление (расширение ADR-071)

- JSON-бэкап комнаты заполняет уже зарезервированный раздел `assets` (`backup.mjs`,
  `format: "remo.board"`, `version: 3`): `{ fileId, sha256, mime, width, height, alt?,
  data: <base64> }` для каждого используемого файла.
- Контрольная сумма считается по всему содержимому, как сейчас.
- Предел бэкапа с файлами — 200 МиБ. Если комната больше, экспорт предлагает «Бэкап без
  изображений» (раздел `assets` содержит метаданные без `data`). Импорт такого бэкапа
  показывает заглушки «Изображение недоступно». Собирать бэкап с файлами целиком в памяти
  нельзя: `buildBoardBackup` и клиентский `verifyBoardBackup` уже держат всё дерево. При
  превышении 200 МиБ сервер отвечает `413 BACKUP_TOO_LARGE` и предлагает «Бэкап без
  изображений»; потоковый формат — отдельное решение, не в v1.
- Импорт с файлами идёт через серверный маршрут `POST /boards/:boardId/backup/import` (право
  `board.edit`): файлы проходят конвейер §4.2 в организацию целевой комнаты, затем `fileId`
  переписываются. Клиентский импорт без файлов остаётся для старых бэкапов.
- Версия формата 3; оба валидатора (`backup.mjs` и `apps/web/src/backupFormat.ts`) принимают
  1, 2 и 3; старые бэкапы без `assets` читаются как раньше. Отдельного раздела `files` не
  появляется — это был бы второй механизм для того же места.

### 5.4 Сборка мусора

Задача `files-gc` раз в сутки:
1. Файл **используется**, если на него ссылается хоть один объект `image` в `widgets` любой
   комнаты организации, включая комнаты в корзине.
2. Неиспользуемому ставится `unreferenced_since = now()`. Если файл снова используется,
   метка снимается.
3. Через 30 дней без использования (дольше окна undo и корзины для платных тарифов) файл
   удаляется: сначала ключи в хранилище, потом `status = 'deleted'` и `deleted_at`.
4. Ключи в хранилище без строки `files` старше суток (сбой посреди загрузки) удаляются по
   префиксу организации.
5. При удалении комнаты из корзины навсегда её файлы попадают в общий цикл через пункт 2.

Квота считает `stored_bytes` только по файлам в статусе `ready`.

## 6. Показ на холсте

Файлы `packages/canvas/src/imagePaint.ts` (отрисовка) и `apps/web/src/imageCache.ts`
(загрузка и кеш).

- **Уровень детализации по экранному размеру объекта:**
  - до 256 px — `w256`;
  - до 1024 px — `w1024`;
  - больше — `w2048`;
  - учитывается `devicePixelRatio`.
  Вариант меняется только после загрузки нового, чтобы не было мигания.
- **Пока картинка грузится**, рисуется прямоугольник цвета `dominantColor` и тонкий значок
  изображения из токенов (§9.6).
- **Кеш** — `createImageBitmap`, LRU с бюджетом 256 МиБ декодированных пикселей. Объекты вне
  экрана не грузятся. Загрузка — не больше 6 параллельно, ближайшие к центру экрана первыми.
- **Ошибка** (`404`, сеть) — заглушка «Изображение недоступно» (§9.6). Повтор — при
  следующем появлении на экране, не чаще раза в 30 с.
- **Слои, выделение, блокировка, комментарии, презентация** — как у фигуры. Изображение
  может быть слайдом.
- **Производительность:** сценарий из `spec`/e2e с 200 изображениями на доске держит те же
  бюджеты кадра, что сценарий 10 000 объектов (`window.__scalePerf`, `paintStats`).

Экспорт синхронный (`renderScope` → `drawWidget`), поэтому перед рендером bitmap'ы
предзагружаются: вариант под разрешение экспорта, ожидание до 15 с, затем заглушка и
предупреждение. Триггер «bitmap загрузился → перерисовать» добавляется в `useCanvasPainting`;
без него картинка появится только после следующего кадра.

### 6.1 Экспорт PNG и PDF

`exportRender.ts` рисует изображения из тех же адресов `/files/...` (тот же источник,
canvas не «пачкается»). Берётся вариант под разрешение экспорта, не больше `w2048`.
Изображение, которое не загрузилось за 15 с, экспортируется заглушкой, а в диалоге экспорта
появляется предупреждение «N изображений не удалось загрузить».

## 7. Квота и тариф

- `storageBytes` по тарифам (`billing-catalog.mjs`): Free 100 МиБ, Pro 2 ГиБ, Team 10 ГиБ,
  Business 25 ГиБ. Окончательные цифры — за владельцем продукта.
- Использование — `sum(stored_bytes)` по организации, считается запросом и кешируется на 60 с
  вместе с правами.
- Превышение квоты после понижения тарифа (§2.5 `spec/billing.md`) ничего не удаляет и не
  скрывает. Блокируются только новые загрузки.
- Self-host (`REMO_BILLING=off`): квоты нет, действуют только технические пределы §2.2.

## 8. Метрики и аудит

- `remo_files_uploads_total{result}` — `ok`, `too_large`, `bad_type`, `quota`, `busy`, `error`;
- `remo_files_bytes_stored` — gauge по установке;
- `remo_files_gc_deleted_total`;
- `remo_files_read_total{variant,result}`.

Аудит: `file.uploaded`, `file.copied`, `file.downloaded_original`, `file.deleted_by_gc`. Без
имени файла в subject: только id.

## 10. Вёрстка: правила

1. **Только компоненты `@remo/ui`** (`basics.tsx`, `fields.tsx`, `display.tsx`,
   `overlays.tsx`, `canvas.tsx`) и существующие оболочки окон (`PanelWindow`, `ObjectBar`,
   `InfoCard`).
   - Нового компонента не хватает — сначала он добавляется в `packages/ui` с описанием по
     шаблону `spec/design-system.md` §16, затем используется.
   - Новые компоненты здесь, скорее всего: `ProgressRing` (если в `display.tsx` нет
     кольца), `UsageBar`, `Lightbox`.
2. **Только токены.** Никаких литералов цвета и размера (правило 6 `AGENTS.md`).
   - Новые токены — в `packages/ui/src/tokens` с обоими значениями тем:
     `image-placeholder-icon`, `image-drop-border`, `image-drop-scrim`, `lightbox-scrim`.
   - Цвета холста — через `canvasTokens.ts`.
   - После правки токенов — `pnpm ds:check`.
3. **Все строки через `apps/web/src/i18n`, RU и EN.** Ключи в группе `image.*` и
   `storage.*`. Тексты из §9 нормативны.
4. **Отрисовка на холсте — в `packages/canvas`** (`imagePaint.ts`, вызывается из `render.ts`
   вместо ветки `unsupported` для `image`). Без React. С юнит-тестом геометрии: вписывание,
   пропорции, выбор варианта по масштабу.
5. **Слои.** Заглушки загрузки рисуются в слое интерфейса над холстом (как `SelectionBadge`),
   а не в документе. Рамка перетаскивания — оверлей уровня приложения.
6. **Окно 900 px.** Окна и панели проверяются на ширине 900 px и на телефоне (ADR-236 и
   §18 `spec/design-system.md`): лайтбокс, окно описания, раздел «Хранилище».
7. **Визуальные эталоны.** Новые состояния снимаются в `spec/ds-baselines` и `spec/baselines`
   (`pnpm baselines`):
   - кнопка на панели;
   - рамка перетаскивания;
   - заглушки: загрузка, ошибка, недоступно;
   - выделенное изображение с ObjectBar;
   - окно описания;
   - лайтбокс;
   - раздел «Хранилище»;
   - светлая и тёмная тема.
   После этого `pnpm e2e:visual`. `ui-inventory` обновляется по процедуре `docs/ui-inventory.md`.
8. **Справка и гайд.** `content/help` (RU и EN), `guide/how-to/` — новая страница «Добавить
   изображение», `guide/reference/limits` — пределы §2.2 и квоты §7, `guide/admin/deploy` и
   `guide/reference/env` — переменные хранилища, MinIO, Yandex Object Storage.

## 11. Тесты

**Юнит:**
- распознавание типа по сигнатуре (PNG, JPEG, WebP, GIF, AVIF; SVG и PDF отвергаются; JPEG с
  расширением `.png` распознаётся как JPEG);
- обработка: EXIF-поворот, удаление GPS (проверка, что в вариантах нет EXIF), прозрачность,
  без увеличения, предел пикселей;
- ключи хранилища: в ключе нет имени файла пользователя;
- `imagePaint`: вписывание, выбор варианта по масштабу и DPR, заглушки;
- `imageCache`: LRU по бюджету, порядок загрузки от центра, повтор не чаще раза в 30 с.

**Драйверы:** общий контрактный набор для `disk` и `s3`. `s3` — против MinIO в
`docker-compose.test.yml` (новый сервис), на тех же тестах.

**С базой:**
- RLS `files`: вторая организация видит 0 строк;
- дедупликация по `sha256` внутри организации и её отсутствие между организациями;
- квота и `402`;
- лимит изображений комнаты;
- чтение: участник комнаты A не читает файл, который есть только в комнате B той же
  организации (§4.3, пункт 2); посетитель по публичной ссылке читает файлы своей комнаты;
- сборка мусора: удалённый объект живёт 30 дней, восстановленный из корзины снимает метку,
  ключи без строки удаляются.

**Безопасность:**
- PNG с внедрённым HTML отдаётся как перекодированный WebP с `nosniff` и
  `sandbox`-CSP;
- «бомба» в 100 млн пикселей отвергается до декодирования;
- поток больше предела обрезается при лживом `Content-Length`;
- `/files/...` без контекста комнаты отвечает `404`.

**Бэкап:** круговой тест «экспорт → импорт в другую организацию» восстанавливает картинки с
новыми `fileId`; бэкап без изображений даёт заглушки; старый бэкап читается.

**Браузер (`pnpm e2e`):**
1. Кнопка → выбор двух файлов → две картинки в сетке, выделены.
2. Перетаскивание файла в точку.
3. Вставка скриншота из буфера.
4. Второй участник видит картинку только после завершения загрузки.
5. Ресайз за угол сохраняет пропорции.
6. Undo удаления возвращает картинку с изображением.
7. Экспорт PNG содержит пиксели изображения (сравнение с эталоном).
8. Квота: на тестовой организации с квотой 1 МиБ вторая загрузка показывает §9.4.
9. Лайтбокс открывается двойным кликом и закрывается `Esc` с возвратом фокуса.

## 12. Этапы (каждый — отдельный PR, каждый проходит `pnpm verify`)

1. **Хранилище и API.** `files-*`, таблица, загрузка, обработка, чтение с проверкой прав,
   драйверы `disk` и `s3`, MinIO в тестовом compose, контрактные тесты.
2. **Холст.** `imagePaint`, `imageCache`, команда `createImage`, кнопка, перетаскивание,
   вставка, заглушки загрузки, ресайз с пропорциями.
3. **Объект целиком.** ObjectBar, замена, описание, лайтбокс, скачивание оригинала,
   доступность.
4. **Квота и хранилище.** Права из биллинга, раздел «Хранилище», плашка квоты, сборка мусора.
5. **Экспорт, бэкап, копии между организациями.**
6. **Эталоны, справка, гайд, `ui-inventory`.**

## 13. Приёмка

1. `pnpm verify --e2e` зелёный с `REMO_FILES_DRIVER=disk` и с `REMO_FILES_DRIVER=s3` (MinIO).
2. На тестовой установке с Yandex Object Storage загрузка, показ, экспорт и сборка мусора
   работают. Бакет приватный, а анонимный запрос к ключу отвечает `403`.
3. Размер документа комнаты с 200 изображениями отличается от пустой комнаты не больше чем
   на 200 КиБ.
4. В вариантах, отданных браузеру, нет EXIF и GPS (проверка `exiftool` в тесте).
5. Доска с 200 изображениями держит бюджеты кадра сценария производительности.
6. Визуальные эталоны §10.7 сняты в светлой и тёмной теме и утверждены.
7. Self-host без S3 и без биллинга: изображения работают на диске, квот нет.

## 14. Решения за владельцем продукта

- Квоты по тарифам (§7) и предел одного файла (20 МБ).
- Хранилище для российской установки: Yandex Object Storage, Selectel или свой MinIO.
- Нужны ли визуальные макеты (Design) до вёрстки или достаточно схем §9 и эталонов §10.7.
