# Токены интеграций

Токен интеграции — способ действовать на доске без браузерной сессии (ADR-096). Он не
заводит вторую систему прав: **токен — это доступ его владельца, сужённый scope**. Что
может человек, создавший токен, — то может и токен; чего не может человек — не может и
токен, даже если scope у токена есть.

## Создание

Только администратор организации (`org_admin`). Секрет вида `remo_it_…` показывается **один
раз**, в базе лежит только его SHA-256.

```sh
curl -X POST https://boards.example.com/orgs/$ORG/integration-tokens \
  -H "Content-Type: application/json" --cookie "$SESSION" \
  -d '{"label":"ci-publisher","scopes":["board.edit"],"expiresInDays":90}'
# → 201 {"token":{"id":"…","label":"ci-publisher","scopes":["board.edit"],"expiresAt":"…"},
#        "secret":"remo_it_…"}
```

| Поле | Правило |
|---|---|
| `scopes` | непустой список из `board.read`, `board.edit` |
| `expiresInDays` | 1…365, по умолчанию 90. «Бессрочно» нельзя: утёкший токен без срока — постоянная дыра |
| `label` | до 120 символов, для человека |

Управление: `GET /orgs/:id/integration-tokens` (без секретов),
`DELETE /orgs/:id/integration-tokens/:tokenId` (отзыв). Создание и отзыв — в аудите
(`integration.token.created`, `integration.token.revoked`).

## Использование

```sh
curl -H "Authorization: Bearer remo_it_…" \
     https://boards.example.com/boards/$BOARD/widgets
```

`POST /boards/:id/commands` — по-прежнему с обязательным `Idempotency-Key`; ключ
считается **в пространстве токена**, поэтому два разных интеграционных токена не могут
переиграть команду друг друга.

## Что можно и чего нельзя

| Действие | Условие |
|---|---|
| `POST /boards/:id/commands` | scope `board.edit` **и** владелец имеет `board.edit` на доске |
| `GET /boards/:id/widgets` | scope `board.read` **и** владелец имеет `board.read` |
| метаданные доски, экспорт, IAM, агенты | только сессия: токен туда не допускается |

Итоговое право = `capabilities владельца на доске` ∩ `scopes токена`. Токен сужает, но
никогда не расширяет.

## Ошибки

| Ответ | Код | Что значит |
|---|---|---|
| `401` | `INTEGRATION_TOKEN_UNKNOWN` | токена нет (опечатка, удалён) |
| `401` | `INTEGRATION_TOKEN_REVOKED` | отозван |
| `401` | `INTEGRATION_TOKEN_EXPIRED` | срок истёк |
| `403` | `SCOPE_REQUIRED` | у токена нет нужного scope (в ответе `scope` для чтения) |
| `403` | `FORBIDDEN` | у владельца нет прав на доске |
| `404` | `RESOURCE_NOT_AVAILABLE` | доски нет или владелец её не видит — существование не раскрывается |

`ACCOUNT_REQUIRED` остаётся для запроса вообще без личности: анонимная ссылка писать не
может.

## Аудит

Команда, выполненная токеном, пишет `actor_type = 'integration'` и `actor_id` = id токена.
Владелец — в строке токена, поэтому «кто это сделал» отвечает одной связью. Отзыв и
создание — отдельные события аудита.

## Границы

- Токен принадлежит человеку: если у него отобрали доступ к доске, токен теряет силу на
  следующем запросе, без отдельного отзыва.
- Нет «токена организации» без владельца. Автоматизация на всю организацию требует токена
  администратора — это честный объём полномочий.
- Содержимое доски токен читает через API (`/widgets`); в события вебхука оно не попадает
  (см. `webhooks.md`).
