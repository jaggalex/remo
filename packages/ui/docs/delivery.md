# Поставка и приёмка

## Пакет

`packages/ui` (`@remo/ui`, исходники TSX, без сборки — как остальные пакеты workspace):

```
src/
  tokens/tokens.json        единственный источник токенов (слой у каждого токена)
  tokens/primitive.css      ┐
  tokens/semantic.css       │ генерируются: pnpm ds:tokens
  tokens/component.css      │ (не править руками — тест сверяет)
  tokens/themes/light.css   │
  tokens/themes/dark.css    ┘ выпуск в продукте — v1.1
  fonts/                    Golos Text + Inter woff2 (latin + cyrillic) + OFL
  components/*.tsx          компоненты; components.css — один слой @layer remo.components
  icons.ts, icons/*.svg     собственный набор, 35 иконок
  i18n.tsx                  контракт строк (ключи); слова — в apps/web/src/i18n.tsx (ds.*)
  canvasTokens.ts           readCanvasTokens() для Canvas 2D painters
  index.ts, styles.css
scripts/                    build-tokens.mjs, contrast.mjs, tokens-lib.mjs
docs/                       брендбук и гайдлайны компонентов
```

- **Каталог** — dev-маршрут `/__ds` в `apps/web` (только `pnpm dev:web`, в сборку не попадает): матрица девяти состояний, все компоненты, переключатели темы, плотности и языка; `?view=board|share|agent` — эталонные экраны. Каталог — часть Definition of Done.
- **Версии** — semver пакета; ломающее изменение токена — major + запись в `packages/ui/CHANGELOG.md` + кодмод, если возможно.
- **Миграция** — сделана: продукт подключает `@remo/ui/styles.css`, старые 18 переменных объявлены алиасами (`--ink → var(--text-primary)`) на один релиз, в `styles.css` нет литералов (тест `apps/web/src/styles.test.ts`), Canvas 2D берёт цвета через `readCanvasTokens()`.
- **Тесты** — `pnpm test` (токены, контраст, литералы, рендер компонентов, литералы в стилях продукта), `pnpm ds:contrast`, `pnpm ds:lint` (stylelint), `pnpm ds:tokens --check`; скриншот-тесты — в v0.2, базовые снимки — `spec/ds-baselines/`.

## Решения

| Вопрос | Решение |
|---|---|
| Тёмная тема | Токены `dark` полные уже сейчас и проверяются тем же тестом контраста; выпуск в продукте — v1.1. |
| Скриншот-тесты | В v0.2; базовые снимки — эталоны `BoardScreen`, `ShareScreen`, `AgentScreen`. |
| Иконки | Собственный набор (35 штриховых, 24×24, обводка 1.75); без покупных библиотек. |

## Добавить компонент

1. Описать по шаблону: назначение → анатомия → варианты → размеры → состояния (все девять, неприменимые — явно) → поведение → a11y → запрещено; для объектов холста — плюс геометрия.
2. Стили — только `var(--…)`, `transparent`, `currentColor`. Новый токен — сначала в `tokens.json`, затем в компоненте.
3. Строки — ключом в `src/i18n.tsx` и переводом `ds.*` в `apps/web/src/i18n.tsx`. Добавить в каталог (`apps/web/src/ds/Catalog.tsx`) во всех состояниях.
4. Прогнать `pnpm ds:check` (токены, контраст, stylelint), `pnpm test` и клавиатурный прогон каталога.

## Приёмка

1. В каталоге есть все компоненты. Для каждого либо показаны все девять состояний в матрице, либо неприменимые объявлены явно — в таблице объявлений каталога и в гайде компонента.
2. Ни один компонент не задаёт цвет или размер литералом (stylelint + тест на `#hex`/`rgb(` вне файла токенов).
3. `pnpm ds:contrast`: все текстовые пары ≥ 4.5:1 — в светлой и тёмной теме.
4. Клавиатура: таб-порядок без ловушек, `Esc` закрывает, фокус возвращается.
5. Три эталона собраны только из компонентов, в двух темах и двух плотностях: 12 снимков в `spec/ds-baselines/`, живые версии — `/__ds?view=board|share|agent`.
6. Плотность меняет высоту контролов 28 ↔ 32 без «прыжков» текста.
7. RU/EN: ни одна строка не обрезается в кнопках и табах на 1280 px.
8. Переключение темы не оставляет ни одного `var()` без значения.
9. Токены проходят линтер именования; дубликатов значений в semantic нет.
10. README пакета объясняет, как добавить компонент, за один экран.
