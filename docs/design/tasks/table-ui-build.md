## 1. Что уже есть и что вы НЕ пишете заново

Поведение уже в `@remo/doc` и `@remo/model`. Ваша задача — UI поверх существующих команд.
Второй путь к той же операции — дефект (AGENTS.md, правило 1).

| Возможность | Команда / модуль | Статус UI |
|---|---|---|
| Авторазмер оси вкл/выкл (ADR-206) | `setAxisAutoResize(board, frameId, axisId, auto)` | нет |
| Размер Авто / пресет / px | `setAxisSize(...)`, ручка `AxisResizeHandle` в `TableAxisControls.tsx` | есть |
| Объединение / разъединение (ADR-204) | `mergeCells(board, frameId, cells)` → `MergeCellsResult`, `splitCell(board, frameId, rowId, columnId)` | нет |
| Дублирование оси (ADR-205) | `duplicateAxis(board, frameId, kind, axisId, { title… })` | нет |
| Перенос в ячейку | `moveSelectionToCell`, `TableCellPanel.tsx`, drop в `gesturePointerMove.ts` | есть |
| Геометрия, хит-тест | `layoutTable`, `tableHitAt`, `cellRect` (`@remo/model`, `@remo/canvas`) | есть |
| Скринридер-зеркало с `colspan/rowspan` | `TableGrid.tsx` | есть |
| Выбор оси | `tableSelection.ts` (`TableAxisSelection`) | есть |
| Рамки и отступы ячеек | — в модели нет | нет, нужен ADR |

Где живёт UI таблицы: `SectionPanel.tsx` (панель раздела), `TableHeaderLayer.tsx`
(заголовки и меню оси), `TableAxisControls.tsx` (+ на краях, ручки размера),
`TableCellPanel.tsx` (ячейка выбранного объекта), `packages/canvas/src/tablePaint.ts`
(живопись сетки), `styles/section-panel.css`, строки — `i18n/{en,ru}-section.ts`.

## 2. Ограничения

- Только токены `@remo/ui`; `pnpm verify` проверяет литералы и лестницу слоёв (ADR-139).
  Нужен новый токен — добавьте в `packages/ui/src/tokens/tokens.json`, затем
  `pnpm --filter @remo/ui tokens`; сгенерированный CSS руками не правится.
- Каждая строка — ключ в `i18n/en-section.ts` и `i18n/ru-section.ts`; без пары не соберётся.
- Файл не больше 800 строк. `SectionPanel.tsx` (609) и `TableHeaderLayer.tsx` (636) близки к
  пределу: новые блоки выносите в отдельные компоненты (`AxisAutoResizeSwitch.tsx`,
  `TableCellMenu.tsx`, `TableRangeToolbar.tsx` и т. п.).
- Любое изменение поведения или модели — сначала ADR в `ADR.md` (часть D обязательно).
- Каждая мутация — команда из `@remo/doc`, одна транзакция, один undo.

## 2.1. Решения по взаимодействию (12.11)

- **Вход в ячейку — клик-клик.** Первый клик по таблице выбирает раздел, второй клик по
  ячейке — ячейку. Заголовок выбирает ось, как сейчас. `Esc` снимает выбор ячейки.
- **`Shift+клик` без выбранной ячейки** — обычное добавление раздела к выделению холста,
  как сейчас. **`Shift+клик` из выбранной ячейки** — расширение диапазона. Это новое
  правило, а не то, что уже различает `tableHitAt`: добавьте шаг в `gestureSteps` с тестом.
- **Авторазмер:** у одной оси — переключатель (`role="switch"`, `aria-checked` true/false);
  у блока — `checkbox` с `mixed` (switch не поддерживает `mixed`).
- **`section.axis.deleteKeepsWidths`** показывается тостом после удаления оси внутри блока.

## 3. Работы по частям

Части независимы; порядок ниже — рекомендуемый. A и C можно начинать до макетов
(механика есть), визуал подставить по макету.

### A. Авторазмер (ADR-206)

1. Переключатель «Авторазмер» оси в панели раздела, в блоке размера выбранной оси:
   `setAxisAutoResize`. Подпись `section.size.autoResize.hint`.
2. Тот же переключатель в меню заголовка (`TableHeaderLayer.tsx`, `menuItems`) — пункт с
   `checked`, вызывает ту же команду.
3. Групповой переключатель блока — в панели, когда выбрана объединённая ячейка: вызывает
   `setAxisAutoResize` для каждой оси блока **в одной транзакции** (`board.transact`), чтобы
   был один undo. Состояние «смешанно», если оси расходятся (`aria-checked="mixed"`).
4. Индикатор «вручную» на холсте — по макету, в `TableAxisControls.tsx` или
   `tablePaint.ts` (решите по макету: DOM, если он фокусируемый; живопись, если нет).
5. После перетаскивания границы — сообщение `section.size.autoResize.offToast` в
   существующий канал уведомлений и в live-region.

### B. Ячейка

1. Состояние «выбранная ячейка / диапазон» — локальное UI-состояние по образцу
   `tableSelection.ts` (новый `tableCellSelection.ts`), не поле документа.
   Если по макету выбор ячейки должен участвовать в общем выделении холста
   (копировать/вставить, Delete) — это новый вид выделения: сначала ADR.
2. Выбор: клик по пустому месту ячейки; диапазон — Shift+клик. Только жесты, которые уже
   различает `tableHitAt`; новых жестов не вводить.
3. Подсветка ячейки и диапазона — по макету; цель drop уже есть (`CellDropTarget`).
4. Меню ячейки (правый клик, `Shift+F10`, клавиша меню) — компонент `Menu` из `@remo/ui`,
   как меню оси. Пункты вызывают существующие команды: вставка оси (`addAxis` с
   `beforeId/afterId`), `duplicateAxis`, `mergeCells`, перенос (`moveSelectionToCell`),
   удаление оси через существующий `AxisDeleteDialog`. Разрушающие — после разделителя.
5. Клавиатура: стрелки двигают выбранную ячейку, Shift+стрелки расширяют диапазон, Esc —
   снять выбор. Порядок Tab — по макету.

### C. Объединение и разъединение (ADR-204)

1. Мини-тулбар над диапазоном и пункт меню ячейки → `mergeCells(cells)`.
2. Отказы `MergeCellsResult.reason` переводите в тексты: несмежный или неполный
   прямоугольник → `section.cell.mergeHint`, заголовок → `section.cell.mergeRefused`,
   заблокированный раздел → существующий `section.locked`.
3. «Разъединить» у выбранной объединённой ячейки → `splitCell(rowId, columnId)` якоря.
4. Объявления в live-region для объединения и разъединения (тексты из макета).
5. Ничего не рисовать для внутренних линий: якорь — единственная ячейка в `grid.cells`,
   живопись уже не проводит линий внутри блока.

### E. Название раздела и переключатель вида (после макета и ADR)

Уточнение: [table-ui-refinement.md](table-ui-refinement.md).

1. Название — `frame.title`, правится на холсте: `patchWidget(board, frame.id, { title })`,
   один undo. Название живёт **вне** прямоугольника таблицы, на `layoutTable`, reflow,
   экспорт и презентацию не влияет. Не даёт дропать объекты.
2. Переключатель «Раздел / Таблица» вызывает **ту же** логику, что панель. Вынесите
   `switchView` из `SectionPanel.tsx` в общий помощник (например,
   `apps/web/src/sectionView.ts`) и вызывайте его из панели и с холста — второй реализации
   быть не должно. Переключение — один undo, выделение и камера не меняются.
3. Замок и только чтение блокируют и название, и переключатель.
4. Порядок: сначала ADR (поверхность переключателя меняет ADR-201), затем компонент
   `SectionTitleBar.tsx` (DOM-слой над холстом, как `TableHeaderLayer`), затем тесты.

### D. Рамки и отступы — после ADR

1. Сначала ADR: новые поля `TableAppearance` (рамки по областям, отступ), их чтение в
   `sanitize.ts`, влияние отступа на геометрию (`TABLE_CELL_PADDING` в
   `packages/model/src/tableGeometry.ts` и `tableReflow`), экспорт и бэкап.
   Без ADR часть D не начинать.
2. Затем: модель + тесты, команда в `@remo/doc` по образцу `setTableFill`,
   живопись в `tablePaint.ts`, UI в группе «Оформление» панели раздела.

## 6. Готово, когда

- Все пункты A–C работают по макету в светлой и тёмной теме; D и E — после ADR и макета.
- Нет литералов цвета и размера; новые токены — в `tokens.json`.
- `pnpm verify --e2e` зелёный.
- Undo каждой операции — один шаг; два клиента видят одно и то же (команды детерминированы).
- В PR: ссылки на кадры макета для каждого состояния и снимки «до/после».

## 7. Нельзя

- Писать вторую модель таблицы или хранить ширину ячейки.
- Добавлять инструмент «Таблица» на рейл или ручки ресайза раздела.
- Обрезать, масштабировать или скроллить объект в ячейке.
- Вводить жесты, которых нет в hit-testing.
- Трогать модель без ADR.
