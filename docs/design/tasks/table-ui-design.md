# Таблица раздела — задание на дизайн UI

Дата: 12 ноября 2026. Исполнитель: дизайнер интерфейса.
Полное ТЗ и обоснования: [table-ui-brief.md](../table-ui-brief.md). Здесь — только то, что
нужно сделать и сдать дизайнеру. Вёрстку делает другой исполнитель по
[table-ui-build.md](table-ui-build.md); ваш результат — его вход.

## 1. Что вы получаете на вход

| Что | Где |
|---|---|
| Визуальный язык «Следы и Поля», правило громкости хрома E2 | [DESIGN.md](../DESIGN.md) |
| Токены (единственный источник цветов, размеров, радиусов, слоёв) | `packages/ui/src/tokens/tokens.json` |
| Карточки уже существующих компонентов таблицы | `packages/ui/docs/components/`: TablePanel, AxisHeader, AxisMenu, AxisSizeMenu, AxisResizeHandle, TableEdgeAdd, CellDropTarget |
| Готовые макеты таблицы T1–T13 (основа для стиля) | холст «REMO — визуальные направления», серия T |
| Решения, которые уже приняты | ADR-196, ADR-199, ADR-201…206 в `ADR.md` |

Холст «REMO» в разделе дизайн-систем на claude.ai — **прежняя** система «Спокойный
инструмент» (заменена ADR-181). Не берите из неё цвета, шрифт и радиусы.

## 2. Правила, которые макет не может нарушить

1. В режиме таблицы раздел **равен** своей сетке; ручек ресайза у раздела нет.
2. Объект **не выходит** из ячейки и **не масштабируется**; если не влезает — растёт ось.
3. Размер не хранится как «ширина ячейки» — он выводится из осей.
4. «Таблица» включается только в свойствах раздела; на холсте — тихие «+ Колонка / + Строка»
   и «+» над границами заголовков. Второй панели «Таблица» на рейле нет.
5. Нет фиксированной ширины с обрезкой, нет скролла внутри ячейки, нет новых жестов,
   которых нет в hit-testing (клик, двойной клик, перетаскивание, правый клик, Shift+клик,
   клавиатура).
6. Все строки — RU и EN; только токены; светлая и тёмная темы.

Если для решения нужно нарушить правило — остановитесь и вынесите вопрос владельцу.

## 3. Объём: четыре части

### A. Авторазмер и блоки (ADR-206)

Модель: у каждой оси два режима — «Авто» (следует за содержимым в обе стороны) и «Вручную»
(растёт под содержимое, но не сжимается сама). Пресеты Узкая/Средняя/Широкая — это
«Вручную». Блок (объединённая ячейка) своего размера не имеет — это сумма осей.

Нарисовать:

1. Переключатель авторазмера оси — в панели раздела рядом с размером и в меню заголовка.
   Состояния: включён, выключен; подпись «Растёт под содержимое, но не сжимается само».
2. Групповой переключатель блока — в панели раздела, когда выбрана объединённая ячейка.
   Состояния: включён, выключен, **смешанно**; что произойдёт при нажатии.
3. Тихий индикатор «ось вручную» на холсте: не спорит с «+» и ручкой размера.
4. Момент перетаскивания границы: значение в px → сообщение «Авторазмер выключен» →
   путь вернуть (двойной клик по границе и кнопка в панели).
5. «До/после» вставки и удаления оси внутри блока по примеру R1 из ТЗ §3.4.1
   (A 200 · B 300 · C 250 → удалить B → A 200 · C 250, блок 750 → 450).
6. Пустая таблица и таблица из одной оси: что показывает переключатель.

### B. Ячейка как объект взаимодействия

1. Состояния ячейки: обычная, hover, выбранная, фокус с клавиатуры, с объектами, пустая.
2. Диапазон ячеек: рамка и подсветка; пересечение с выделенными объектами.
3. Цель перетаскивания: можно положить; нельзя (заголовок); раздел заблокирован.
4. Меню ячейки (правый клик и `Shift+F10`): вставить из буфера, переместить сюда, вставить
   строку/колонку, дублировать строку/колонку, объединить, удалить. Разрушающие — внизу,
   после разделителя.
5. Пустая ячейка: решить, нужен ли «+» или подсказка, или это шум. Дать рекомендацию.

Решить и обосновать: чем выбранная ячейка отличается от выбранного объекта и выбранной оси,
оставаясь в одном семействе; диапазон — заливка или контур; меню у курсора или у угла.

### C. Объединение и разъединение (ADR-204)

1. Точка входа: мини-тулбар над диапазоном **и** пункт меню ячейки. Оба состояния.
2. Объединённая ячейка без внутренних линий; как видно, что она объединена, когда выбрана.
3. «До/после»: объекты из накрытых ячеек переходят в якорную (левую верхнюю).
4. Разъединение: где кнопка; объекты остаются в якорной ячейке.
5. Запреты: несмежный выбор, захват заголовка — тексты и тон (не ошибка, а объяснение).
6. Текст объявления для экранного диктора при объединении и разъединении.

### D. Рамки и отступы

1. Группа «Оформление» в панели раздела: к заливкам добавить «Рамки» и «Отступы в ячейках»
   так, чтобы группа не стала свалкой (свёрнута по умолчанию, как сейчас).
2. Область: таблица, шапка, колонка, строка, ячейка — и как выбирается конкретная ячейка.
3. Рамка: цвет, толщина, стиль; вся ячейка или по сторонам — **предложите одно**.
4. Отступ: пресеты S/M/L или число; текущее значение и «по умолчанию»; «Как было» у каждого
   параметра.
5. Крайние случаи: без заливок; заливка + рамка; длинный заголовок; пустая таблица;
   тёмная тема на пользовательских заливках (контраст).

Внимание: рамок и отступов в модели **ещё нет**. Ваш макет — основа для ADR; любые
параметры, которых нет в макете, в модель не попадут.

## 4. Требования к макетам

- Размеры экрана: 1280×720 и 1680×1050. Канвасные элементы — ещё при 50 % и 200 %: их
  размер в экранных px не меняется.
- Каждое новое состояние — в светлой и тёмной теме.
- Новый токен — имя и пара значений light/dark в таблице «элемент → токен»; hex в макете
  не нужен. Существующий токен — по имени из `tokens.json`.
- Данные настоящие: «Задача / Ответственный / Срок», «Собрать макет / Аня / 12.11»,
  заметка, карточка и фигура в ячейках, пустая ячейка, длинный заголовок, блок 2×2.
- Клавиатура: focus-ring, порядок Tab, имена для скринридера текстом, тексты live-region
  для переключения размера и объединения.
- Движение 120–160 мс без пружин; с `prefers-reduced-motion` — без анимации.
- Термины: «колонка», «строка», «ячейка», «блок» (не «мердж»), «авторазмер».

Строки — из ТЗ §8 (ключи и RU/EN). Предел длины: RU до 28 символов, EN до 34; проверяйте
макет на самой длинной строке. Новые строки добавляйте в ту же таблицу.

## 5. Что сдать

1. Figma, страницы: `00 Context`, `10 Size modes`, `20 Cell`, `30 Merge`, `40 Appearance`,
   `90 Components`, `99 Redlines`.
2. Имена кадров: `size / axis-auto`, `size / block-mixed`, `cell / hover`,
   `merge / selected-range`, `appearance / borders-open` и т. п. — по шаблону
   `<часть> / <состояние>`.
3. Компоненты с вариантами «состояние × тема × disabled»; мини-тулбар диапазона — отдельно.
4. Redlines: отступы, радиусы, толщины, зоны попадания (не меньше 24 px, на касании 44),
   z-порядок над холстом, поведение при зуме.
5. Прототип трёх сценариев: «положить объект в ячейку», «объединить и разъединить»,
   «выключить и включить авторазмер».
6. Таблица «элемент → токен → light/dark».
7. Список решений по открытым вопросам из §3 (B, C, D) — одной строкой каждое, с причиной.

## 6. Приёмка дизайна

| Проверка | Критерий |
|---|---|
| Инварианты §2 | ни один кадр не показывает обрезку, скролл в ячейке, ресайз раздела |
| Темы | у каждого нового состояния есть пара light/dark |
| Токены | каждый цвет и размер назван токеном или предложен как новый с парой значений |
| Строки | у каждой надписи есть ключ и RU/EN, длины в пределах |
| Состояния | для A–D нарисованы все пункты §3 |
| Клавиатура | показан фокус и порядок Tab для панели, меню ячейки и тулбара диапазона |
| Решения | каждый вопрос «решить» закрыт одной рекомендацией |

Два круга правок; после первого — созвон 30 минут по спорным местам.

## 7. Что уже работает и не требует макета

Сетка, шапка, заливки; добавление/вставка/переименование/поворот/перемещение/удаление осей;
размеры Авто/пресеты/px и ручка на границе; перенос объектов между ячейками и «Переместить
в ячейку…»; дублирование оси (команда есть, нужен только пункт меню); объединение и
разъединение (команды есть, нужен только UI); чтение таблицы скринридером.

Открыто, можно решить по ходу: должен ли блок «переякориваться» при удалении якорной оси
(сейчас блок снимается). Если да — это отдельное правило и ADR, вынесите владельцу.
